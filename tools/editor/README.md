# 데이터 에디터 (Data Editor) — 로컬

장소(`districts.js`), 랜드마크 드랍(`landmarks.js`), 메인 퀘스트(`mainQuests/` 폴더), 아이템·밸런스 등을
**로컬에서 읽어 웹 UI로 수정한 뒤, 로컬 git으로 커밋·푸시**하는 도구입니다.

## 동작 방식

- 데이터는 **로컬 파일**에서 읽습니다 (GitHub API/PAT 불필요).
- 저장 시 변경된 **데이터 객체 블록만** 재직렬화 → 로컬 디스크에 기록 →
  `serve.js`가 현재 git 브랜치로 `git commit` + `git push` 합니다.
- 파일 헤더·헬퍼 함수·export·바깥 주석은 그대로 보존됩니다.

## 실행

저장소 루트에서:

```bash
node serve.js
```

브라우저(자동으로 열리며, 안 열리면 직접):

```
http://localhost:8080/tools/editor/
```

> **node 20 이상**으로 띄우세요 — `📋 대장` 탭의 감사가 `js/data/*.js`를 ESM으로 읽습니다.
> 포트가 이미 쓰이고 있으면 `PORT=8099 node serve.js`로 바꿀 수 있습니다.
>
> `serve.js`는 로컬 전용(`127.0.0.1`)이며, 데이터 읽기/저장/푸시 API(`/api/*`)를 제공합니다.
> 쓰기는 화이트리스트 파일로만 제한됩니다 — 장소·랜드마크·랜드마크 카드 메타, 퀘스트(`mainQuests/` 폴더의
> `global.js` + 6직업 × `{shared,branch_a,branch_b}` 19파일), 아이템 소스 9파일, 밸런스.
>
> **퀘스트 편집 경로**: 게임이 실제 로드하는 소스는 `mainQuests/index.js`가 병합하는 직업별 폴더입니다.
> 에디터 퀘스트 탭은 이 19개 파일을 병합해 보여주고, 수정 시 각 퀘스트의 원래 소스 파일로 저장합니다
> (아이템 탭이 9개 소스를 병합 편집하는 것과 동일). 과거의 단일 평면 파일 `mainQuests.js`는 제거되었습니다.

## 사용법

1. 접속하면 **자동으로 로컬 데이터를 불러옵니다** (상단에 현재 브랜치 표시).
2. **장소 / 랜드마크 / 퀘스트** 탭에서 수정합니다.
   - 모든 목록 탭(공용 변수·장소·랜드마크·세부장소·퀘스트) 왼쪽 리스트 상단에 **🔍 검색**이 있습니다 — 이름·ID(퀘스트는 캐릭터, 공용 변수는 한글 라벨)로 즉시 필터됩니다.
   - 드랍 테이블: weight 옆에 실시간 **드랍 %** 표시.
   - 존재하지 않는 아이템 ID는 빨간 테두리로 경고.
   - 퀘스트: `prerequisite`(선행)로 **연계 체인** 편집 + 후속 퀘스트 표시.
3. **복사/붙여넣기** — 같은 내용을 여러 곳에 넣을 때. 각 상세 헤더의 **📋 복사** → 해당 탭 상단에 뜨는 붙여넣기 패널에서 처리합니다. 대상에 따라 동작이 다릅니다:

   | 복사 대상 | 붙여넣기 동작 | 비고 |
   |-----------|---------------|------|
   | **세부장소** | 선택한 랜드마크들에 **복제** | 파생 카드(`sl_<id>`) 충돌 방지를 위해 **id 자동 고유화** |
   | **랜드마크** | 선택한 구들에 **연결**(참조 추가) | 같은 랜드마크 카드가 여러 구의 top 슬롯에 표시. 이미 연결된 구는 ✓·비활성 |
   | **구(장소)** | 같은 설정의 **새 구 N개 복제** | 키·내부 `id` 자동 생성, 이름에 `(복사)` 표기. ⚠️ 인접 구(`adjacentDistricts`)·퀘스트 참조는 자동 연결 안 됨 — 생성 후 확인 |
   | **아이템** | 같은 설정의 **새 아이템 N개 복제** | 원본과 같은 소스 파일에 생성, 키·내부 `id` 자동 생성, 이름에 `(복사)` 표기. ⚠️ 새 아이템은 `stackConfig.js`·CardFactory `CARD_IMAGES`·구/랜드마크 드랍에 **자동 등록 안 됨** — 필요 시 등록 |

   - 세부장소·랜드마크 패널은 대상을 **여러 곳 동시 선택**(전체 선택/해제 지원), 구 패널은 **개수**를 지정해 한 번에 생성합니다.
4. **신규 추가** — 각 목록 탭에서 새 항목을 빈 골격으로 만듭니다(ID/이름 입력).
   - **장소**: 사이드바 `+ 장소(구) 추가` · **랜드마크**: `+ 랜드마크 추가`(카드 메타 동시 생성) · **세부장소**: 랜드마크 그룹의 `+` · **아이템**: `+ 새 아이템 추가`(보던 아이템과 같은 소스 파일에 생성) · **퀘스트**: `+ 새 퀘스트 추가`(보던 퀘스트와 같은 소스 파일에 생성, 선택 없으면 공통 `global.js`).
   - 복잡한 항목(효과 많은 아이템 등)은 빈 골격보다 비슷한 항목을 **📋 복사**하는 편이 빠릅니다.
5. **⚙️ 설정** 탭에서 커밋 메시지를 바꿀 수 있습니다.
6. 우상단 **[저장 (커밋&푸시)]** → 로컬 기록 + 현재 브랜치로 커밋·푸시.

### 📋 대장 탭 — 아이템 세팅이 잘못된 카드를 한눈에

아이템 659종을 전수 감사해 **4단계로 분류**합니다. `⚠️ 검증` 탭이 "없는 ID를 가리키는가"(참조 무결성)를
보는 것과 달리, 대장은 **아이템 자체의 세팅**을 봅니다 — 선언한 효과가 실제로 배선됐는지, 획득 경로가
있는지, 값이 화면에 뜨는지.

| 상태 | 뜻 |
|------|-----|
| **배선 문제** | 죽은 필드(코드 전체 grep 0건) · 획득 경로 없음 · 사용처와 기능이 모두 없음 |
| **표시 누락** | 동작은 하는데 값이 화면 어디에도 안 뜬다 (도구 패시브 `onUse`가 대표적) |
| **참고** | 읽히지 않는 잔여 플래그, `stackConfig` 값 불일치, 이미지 미등록 — 동작 영향 없음 |
| **정상** | 지적 사항 없음 |

판정은 **배타적**입니다 — 아이템 1개당 상태 1개이고, `배선 문제 > 표시 누락 > 참고` 순으로 대표 상태가
정해집니다.

#### 지적마다 "어떻게 고쳐라"가 붙습니다

대장을 보는 사람은 코드를 고치지 않으므로, 지적마다 **담당**과 **실행 지시**를 함께 보여줍니다.

| 담당 | 뜻 |
|------|-----|
| 🧩 **기획에서 수정 가능** | 에디터에서 데이터만 고쳐 해결됩니다. 어느 탭 어느 필드를 어떻게 만지는지가 적혀 있습니다 |
| 🔧 **개발 배선 필요** | 읽는 코드가 없어 데이터만 고쳐도 동작하지 않습니다. 개발자에게 넘기고, 그때까지는 설명문이 없는 효과를 약속하지 않게 문구만 맞춥니다 |

**담당 칩으로 걸러서** "지금 기획이 손댈 수 있는 것만" 볼 수 있습니다. 개발 배선이 필요한 항목을
기획자가 붙들고 있으면 시간만 버리므로, 이 구분이 안내의 핵심입니다.

안내는 아이템별 맥락을 반영합니다. 예를 들어:

- **획득 경로 없음** → `lootTable`/`output` 중 어디에 넣을지 세 갈래로 제시하고, **그 카드를 재료로 요구하는
  레시피가 있으면 함께 경고**합니다 — 송이버섯은 *"지금 2곳이 이 카드를 재료·도구로 요구합니다(원기 회복탕,
  버섯 리조토 조리) — 얻을 수 없으니 그 제작도 영구히 막혀 있습니다."*
- **표시 누락** → 배율을 어떻게 문장으로 쓸지 예문까지 만들어 줍니다 — `coldResistMult: 0.5`면
  *"설명문에 '50% 감소' 또는 '50%로 감소'처럼 적으면 플레이어가 볼 수 있습니다."*
- **사용처 없음** → 설명문이 약속한 내용을 인용해 *"그 약속을 지키는 쪽으로 맞추는 게 먼저입니다"*라고 짚습니다.
- **stackConfig 불일치** → **실제 적용되는 값**을 알려 주고, 아이템 탭에서 숫자를 바꿔도 반영되지 않는다고 명시합니다.

- 상단 **상태 카드 4장**을 누르면 그 상태만 봅니다. 종류 칩(소비품·재료·구조물…)·담당 칩과 함께 걸립니다.
- **검색**은 이름·ID·설명뿐 아니라 **지적 내용·안내 문구·획득처 라벨**까지 훑습니다 — `onUse`,
  `CARD_IMAGES`, `stackConfig`로 문제 유형을 찾고, `강남`처럼 **구 이름**으로 드랍 위치를 찾을 수 있습니다.
- 행을 펼치면 지적 사항 + **획득처 / 사용처 전체 경로**가 나옵니다. 획득처는 드랍표(구·랜드마크·세부장소·적)
  · 제작 결과물 · 퀘스트 보상 · 덫 포획 · 분해 산출 · 시작 장비 · 시스템 산출 등을 모두 포함합니다.
- **→ 아이템 탭에서 편집**을 누르면 그 아이템 편집 화면으로 바로 넘어갑니다. 고친 뒤 우상단
  **[저장 (커밋&푸시)]** 하면 판정이 자동으로 무효화되고 다음에 대장을 열 때 재계산됩니다
  (즉시 보려면 **🔄 다시 검사**).
- **아이템 탭 사이드바의 점**이 같은 판정을 색으로 보여줍니다 — 편집 중에도 문제 여부가 보입니다.
  탭 이름 옆 숫자는 `배선 문제 + 표시 누락` 합계입니다 (참고는 세지 않습니다).

판정 엔진은 `tools/audit-items.mjs`입니다. 에디터 없이 터미널에서도 돌아갑니다:

```bash
node tools/audit-items.mjs                # 요약 + 배선 문제·표시 누락 목록
node tools/audit-items.mjs --status=info  # 특정 상태만
node tools/audit-items.mjs --json         # 에디터가 쓰는 원본 JSON
node tools/audit-items.mjs --unclassified # 역할 미분류 경로 (엔진 사각지대 점검)
```

> ⚠️ **node 20 이상이 필요합니다.** node 16에서는 `js/data/*.js`를 ESM으로 읽지 못해 감사가 실패하고,
> 에디터에는 "node 20 이상으로 serve.js를 다시 실행하세요" 안내가 뜹니다. `serve.js`는 **자기를 실행한
> 것과 같은 node**로 감사를 돌리므로, `serve.js`부터 node 20으로 띄워야 합니다.
>
> 아이템 ID의 획득/사용 경로는 손으로 열거하지 않고 `js/data/` 전체를 재귀로 훑어 **역할 키**로
> 분류합니다(`lootTable`·`output`·`requiredItems`·`trapData`…). 새 데이터 구조를 추가했는데 대장이
> 엉뚱하게 "획득 경로 없음"이라고 하면 `--unclassified`로 미분류 경로를 확인하고
> `audit-items.mjs`의 `ROLES` 표에 한 줄 등록하세요.

### 드랍 표는 3계층 — 각각 다른 탭에서 편집합니다

게임은 **어디에 서서 탐색했는지**에 따라 서로 다른 표를 굴립니다. 세 표는 데이터·코드 모두 분리돼 있어
한쪽을 고쳐도 나머지는 바뀌지 않습니다.

| 계층 | 언제 쓰이나 | 에디터 위치 | 데이터 |
|------|-------------|-------------|--------|
| **구(표면)** | 구에 서서 탐색 | **장소** 탭 → `lootTable (탐색 드랍 가중치)` | `districts.js` → `DISTRICTS[구].lootTable` |
| **랜드마크 자체** | 랜드마크 안(세부장소 밖)에서 탐색 | **랜드마크** 탭 → `lootTable (랜드마크 전용 드랍)` | `landmarks.js` → `LANDMARK_DATA[키].lootTable` |
| **세부장소** | 세부장소 첫 진입 | **세부장소** 탭 → `lootTable (세부장소 드랍)` | `landmarks.js` → `subLocations[].lootTable` |

- 세 표 모두 `weight`(가중치) + `min`/`max`(1회 드랍 수량 `minQty`/`maxQty`) 열을 가집니다. `min`을 비우면 수량 1개 고정입니다.
- `lootCount min/max`는 **탐색 1회에 뽑는 픽 수**입니다(구는 이 필드가 없고 공용 변수 `explore.lootCountMin~Max`를 씁니다).
- **자원(`cls`)·제철(`seasons`)·오염% 열은 구 표에만 있습니다** — 랜드마크·세부장소 표에는 적용되지 않습니다.
- 랜드마크 자체 표는 **재고·1회 제한이 없어 탐색마다 반복 획득**됩니다. 세부장소 표는 첫 진입 1회만 나오고 재고가 차감됩니다.
  같은 아이템이라도 어느 계층에 넣는지에 따라 획득량이 크게 달라집니다.
- 전용 표가 없는 랜드마크(베이스캠프)는 `+ 전용 드랍 표 만들기` 버튼으로 새로 만들 수 있습니다.

> 계층별 동작 차이·전체 확률표: [`docs/analysis/LANDMARK_LOOT_TABLE.md`](../../docs/analysis/LANDMARK_LOOT_TABLE.md) ·
> 구 표면 상세: [`docs/analysis/DISTRICT_LOOT_TABLE.md`](../../docs/analysis/DISTRICT_LOOT_TABLE.md)
> (랜드마크 문서는 데이터 수정 후 `node scripts/generate_landmark_loot_doc.mjs`로 재생성)
