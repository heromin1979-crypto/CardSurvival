# 미니맵 구역 폴리곤 추적 (minimap district tracing)

`js/ui/SeoulMapModal.js`의 `DRAWN_MAP_DISTRICTS` 폴리곤(마우스오버 포커스 히트존)을
블루프린트 지도 아트워크에서 **자동 추적**하는 파이프라인.

폴리곤은 손으로 유지보수하지 않는다. 지도 아트워크
(`assets/images/ui/minimap-map/seoul-blueprint-map-final00-clean.png`, 2752×1536)가
바뀌면 이 스크립트로 다시 생성한다.

## 실행 (repo 루트에서)

```bash
python3 tools/minimap-trace/segment.py   # 구역 세그멘테이션 → _out/lab.npy
python3 tools/minimap-trace/extract.py   # 폴리곤 추출 → _out/districts.js.txt
```

`_out/districts.js.txt` 내용을 `SeoulMapModal.js`의 `DRAWN_MAP_DISTRICTS` 블록에 붙여넣는다.

의존성: `numpy`, `scipy`, `Pillow` (skimage 불필요).

## 동작 방식

1. **실루엣**: 밝은 경계선의 최대 연결성분을 채워 서울시 외곽을 얻는다.
2. **벽 마스크 = 연결된 경계선 네트워크만**: 실제 구 경계선 + 해안선은 하나의
   연결성분으로 이어지고, **라벨 글자·해칭은 분리된 작은 blob이라 제외**된다.
   → 지도 위 인쇄 글자를 이미지에서 지우지 않아도 히트존이 글자에 영향받지 않는다
   (= "글자 뺀 외곽으로 영역 따기"를 이미지 편집 없이 구현).
3. **세그멘테이션**(`segment.py`): 각 구 라벨 위치를 시드로, 경계선 네트워크를
   고비용 장벽으로 삼아 Dijkstra 분할(내부는 비용 1 → 거리 기반). 한강은 중심선
   장벽으로 남/북 분리. 좌표계 = 이미지/2 = **1376×768** (= `MAP_W`×`MAP_H`).
4. **추출**(`extract.py`): 구역 마스크 → Moore 경계추적 → Douglas–Peucker 단순화.
   도시 밖 빈 영역(북서 로브·프레임 스트립)은 은평구 실제 상단 경계 폴리라인으로 클리핑.

## 좌표계 정합

폴리곤 좌표 = 아트워크 픽셀/2. `SeoulMapModal.js`가 이 이미지를 SVG `<image>`로
직접 임베드(`viewBox="0 0 1376 768"`)하므로 히트존이 그려진 경계선과 픽셀 단위로 정합된다.

시드 좌표(구 라벨 위치, 688-space)는 `segment.py`의 `seeds` 딕셔너리에 있다.
분할이 어긋나면 해당 구의 시드 좌표를 조정하거나 `MANUAL`에 장벽 폴리라인을 추가한다.

## 셀 스냅 (extract.py)

Dijkstra 결과를 그대로 쓰지 않고, 그려진 선 네트워크로 둘러싸인 **셀** 단위로
스냅한다: 한 구가 셀 표의 90% 이상이면 셀 전체를 그 구로 확정(경계 = 그려진 선과
정확히 일치), 혼합 셀은 플러드 분할 유지. 테두리 연결 셀(여백)은 항상 미할당.
셀 벽 = **벽 마스크 전체**(≥800px 비-텍스트 밝은 성분 전부, 최대 성분만이 아님 —
떨어져 있는 둑선·경계선도 벽이 됨) + `MANUAL` 실링 스트로크(점선/희미한 경계 분할).
벽 마스크는 `_out/check_wallmask.png`로 확인 (노랑 = MANUAL 실링).

물에도 같은 원리를 적용한다:
- **물 셀 스냅**: 물 대역이 셀의 45% 이상을 덮으면 셀 전체를 물로 확정
  → 강변 구 경계가 그려진 둑 선에 정확히 안착.
- **반환(reclaim)**: 반대로 대역이 구에 스냅된(≥90%) 셀을 침범한 픽셀은
  육지로 반환 (동쪽 치수선 구역 x≥1100 제외 — 그쪽 수로는 빈 그리드 셀과
  붙어 있어 물로 유지해야 함).
→ 손으로 딴 대역은 "수로를 대충 덮기만" 하면 되고, 최종 경계는 셀이 결정한다.

## 한강 처리

`segment.py`의 `river` 폴리라인은 실제 수로를 손으로 딴 것(북서 지류 + 본류,
688-space, 폭 `RIVER_W`). 이 대역은 ① 플러드 장벽(어느 구도 물을 못 가짐)이고
② `fill_holes(net|band)`로 실루엣을 밀봉(마포처럼 둑 틈으로 여백에 새는 지역
방지)한다. extract 마지막에 플러드의 -1 픽셀을 다시 0으로 만들어 셀 스냅이
물 위로 칠한 부분을 걷어낸다.

동쪽 절반(work x 680~1126)은 손 폴리라인이 어긋나서 **둑 추적**으로 대체:
검증된 수면 픽셀 (830,442)에서 시작해 컬럼별로 위/아래 둑 선에 스냅하며 행진
(`_track`), 미추적 컬럼(다리·희미한 둑)은 보간으로 메운다. 역방향 추적은
x=680에서 멈춘다 — 그보다 서쪽은 여의도 합수부라 섬의 밝은 순환도로에
잘못 스냅되기 때문. 그 구간은 폴리라인 + `WATER` 스트로크가 담당한다.

### 여의도
- 북수로(Han River 라벨 수로)는 `river` 폴리라인이, 섬 동쪽의 넓은 합수부는
  `WATER` 추가 스트로크 2개가 물 대역으로 덮는다.
- **샛강(남수로)은 의도적으로 물 대역에서 제외** — 섬이 클릭 가능 영역으로
  남게 하기 위함. 대신 플러드가 동작구 쪽에서 먼저 도달할 수 있어,
  `extract.py`가 섬+샛강 성분(bbox 510–602 × 443–502, 시드 (545,470))을
  **영등포구로 강제 할당**한다.

## 알려진 아트워크 보정 (아트워크 변경 시 좌표 갱신 필요)

- **금천|관악 경계**: 원화 경계선이 점선/끊김 → `MANUAL` 스트로크로 봉합.
  스트로크는 반드시 **실제 점선 위**에 놓여야 한다 — 벗어나면 플러드가 스트로크에서
  갈라져 그 사이 띠가 엉뚱한 구로 넘어간다 (남쪽 끝은 도시 남단선 안쪽에서 마감,
  넘치면 경계선 아래로 수염 스파이크 발생 → `extract.py`의 금천 SE 클립이 백업).
- **강서 서해안 틈**: `MANUAL` 두 번째 스트로크로 봉합 (없으면 북서 지역이
  여백으로 새서 실루엣에서 빠짐).
- **구로|영등포 경계 (도림천)**: 희미한 이중 하천선이라 벽 마스크가 못 봄
  → `MANUAL` 스트로크로 봉합.
- **북서 지류**: 상류(x<415)는 북동쪽 둑 선이 아예 없음(수로가 그리드로
  페이드) — 그쪽엔 구가 없어 무해. 마포 구간(x 415~510)은 수로 폭 ~50px라
  `WATER` 스트로크(폭 46)로 전체를 덮는다. 지류 출구 실링은 `MANUAL` 마지막
  스트로크.
- **강동 동쪽 치수선 포켓**: `extract.py`의 `_POCKETS` 프로브 셀 강제 미할당.
- **은평 북서 상단**: 실제 상단 경계 폴리라인으로 클리핑.
