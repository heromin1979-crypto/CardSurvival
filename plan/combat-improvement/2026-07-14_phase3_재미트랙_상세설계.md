## F1. 적별 텔레그래프-카운터 설계표 (일반 12종)

**공통 구현:** `js/data/enemies.js` specialSkills에 `telegraphTurns`(예고 턴 수)·counterHint 추가 →
`CombatAiTurns._decideNextIntent`가 예고 인텐트(아이콘+카운트다운, timedThreat와 동일 UI 계약) 생성 →
`_runSingleEnemyTurn`에서 예고→발동, 카운터 조건 판정. 적별 계약 단위테스트 + `combat.*` ko/en 로케일.

|---|---|---|---|
| `zombie_common` | 기본 근접 | **변경 없음** — 기준선 적. 모두가 특수하면 특수함이 죽는다 | - |

## F2. 위치 공격 — 진형을 부수는 적 2종

- **신규 이펙트** `forcedMove`: `CombatRankedEffects._applyRankedEffect`에 케이스 추가 —
  `moveCombatant(formations, targetId, rank ± distance)` 재사용. 점유 슬롯이면 Phase 2 스왑 규칙,
  4랭크 벽이면 이동 대신 고정 피해(밀 곳이 없을 때의 압박).
- **`zombie_charger`**: charge_strike 발동 시 넉백 1랭크 — 전열 근접 캐릭터가 스킬 잠금(usableFrom) 상태가
  되므로 복귀 이동이 실제 턴 비용이 된다.
- **`raider_elite` 또는 신규 적 1종**: '갈고리 끌기' — 후열 아군을 전열로 끌어옴. 원거리 캐릭터 보호가 과제화.
- **위치 시너지 체감선 상향** (제안, F6 확정): `backlineRangedAccBonus` 0.05 → 0.10,
  전열 근접 피해 ×1.05 → ×1.10. 현재 값은 존재를 모를 수준.
- 회귀 테스트: 강제 이동 후 진형 불변식(전열 최소 1, 4칸 초과 금지), 넉백 시 스킬 잠금 상태 전이.

## F3. 직업별 셋업→페이오프 스킬 재설계

**현황:** doctor(diagnose→vulnerable ×1.3)·homeless(scavenge→improvised ×1.3)만 2턴 계획이 성립.
나머지 4직업은 셋업 토큰이 없다. **원칙: 스킬 추가 없이 기존 3종의 효과를 연결로 보강.**

| 직업 | 현재 3종 | 개선안 | 정체성 |
|---|---|---|---|
| doctor | precise_cut / triage / diagnose | **유지** (성립 모델) | 해부학적 정밀 |
| homeless | dirty_fighting / slip_away / scavenge | **유지** | 임기응변 |
| soldier | burst_fire / suppressive_fire / tactical_shift | tactical_shift(이동+1)에 **focus 토큰 1 부여** — "물러나며 조준" → 다음 burst_fire 치명 +15%p | 사선 관리 |
| firefighter | axe_swing / rescue_guard / force_advance | force_advance(이동-1)에 **strength 토큰 1 부여** — "돌파 전진" → 다음 axe_swing ×1.3 | 돌파 탱커 |
| chef | knife_flurry / field_ration / hot_pan | knife_flurry에 **상태이상(burn 등 DoT) 대상 +50% 피해** — hot_pan(burn 45%)이 셋업이 됨 | 굽고 썰기 |
| engineer | wrench_strike / improvised_cover / shock_trap | wrench_strike에 **제어 상태(shock/rooted) 대상 치명 확정** — shock_trap(60%)이 셋업이 됨 | 제어→처벌 |

- 구현: `combatSkills.js` SUPPORT_EFFECTS에 토큰 병기(effects 배열에 token 추가),
  조건부 보너스는 `_applyRankedDamageEffect`에 대상 상태 검사 1개 지점 (chef/engineer 공용 규칙:
  `bonusVs: { statusIds: [...], mult / critAuto }` 스킬 필드로 데이터화 — 하드코딩 금지).
- 스태미나 압박: 대표 공격 스킬 2→3 상향 검토(F6 시뮬로 "기본공격으로 버티는 턴" 발생률 확인 후 확정).
  basic_strike 1 유지.
- 신규 표기 전부 `combat.skill.*` ko/en + `BAL_HELP`(신규 밸런스 키) 등록.

## F4. 약점 발견·표기

- 기록 지점: `CombatRankedEffects._applyRankedDamageEffect`의 약점 로그 분기(affinity > 1)에서
  `GameState.flags.enemyWeaknessSeen[enemy.id] = true` (구세이브는 Object.assign 병합으로 자연 호환).
- 표기: `CombatUI._renderCombatant` 인텐트 배지 옆 무기 타입 아이콘 (`weaknesses` 배열 → 이모지 매핑).
  발견 전에는 미표시 — 첫 발견의 "아하"와 다회차 지식 축적(필러 3)을 동시에.
- 시크릿 보스 21종 포함 33종 공통 적용. 단위테스트: 발견 전 미표시/발견 후 표시/세이브 왕복 유지.

## F5. 스트레스 긴장 구간 + 도주의 전략화

**현황:** 임계(10) 도달 시 각오 10%(strength 1)/붕괴 90%(vulnerable 1)는 이미 구현
(`CombatStatusSystem.addStress`). 문제 두 가지 — ① 실플레이 평균 스트레스 2.9/10로 임계 도달이 드묾
② 도달해도 토큰 1개라 드라마가 없음.

- **긴장 구간 신설**: 스트레스 7+에서 '동요' 상태 — 명중 -5%p(`_rankedAimProfile`에 modifier 1개),
  UI에 스트레스 게이지 색 전환. 임계 전부터 스트레스 관리 스킬(nurse_encourage -12 등)의 가치가 생긴다.
- **붕괴 강화**: vulnerable 1 + **다음 턴 무작위 스킬 1개 잠금** ("손이 떨려 …를 쓸 수 없다" 로그) —
  무너짐이 행동으로 보이게. 각오는 strength 1 + afterResolve 4→3 (더 오래 유지되는 보상).
- **도주 전략화**: `fleeChance 0.6` 고정 → 상황식 —
  기본 0.5 + 적 전열 공백 +0.2 + 자신 speed 토큰 +0.15 + 적 전원 기절/hesitation +0.15 (상한 0.9).
  `homeless_slip_away`는 +0.2 고유 보정으로 직업 정체성 유지. 실패 배율(×1.5 피격)은 유지 —
  "도주각을 만드는 턴"이 유효 전술이 된다. 도주 성공 시 전리품 포기 명시(Scarcity — 이겨서 얻을 것과 비교).
- 구현: `gameBalance.js combat.stress`·`combat.flee` 블록 확장 + BAL_HELP 등록, `_fleeAction` 개조.

## F6. 밸런스 확정 (F1~F5 반영 후 일괄)

1. F1~F5는 적을 강하게(acid 중첩·horde 집중·저격 예고)도 약하게(brute 회피 가능)도 만든다 —
   **개별 조정 없이 완료 후 `--n 100` 스팟 재측정부터.**
2. Phase 2 이관분 판정: DL5 실플레이 40~60% (부족 시 DL5 조우 테이블 상위 적 비중 조정),
   약탈자 상성 스프레드(raider_elite 조준 예고가 권총 유저에게 회피 수단을 주므로 재측정 후 판단),
   3v2 템포(soldier_suppressive_fire 2타겟 선례에 맞춰 마체테 '휩쓸기' 전열 2타겟 ×0.7 검토).
3. 확정: `--n 1000` × 2조건 리포트 커밋 + `BASELINE_2026-07-13.md` 비교표 갱신. 판정은 소음45 셀.

## 실행 순서와 검증

```
F1(12종 계약, 3~4일) → F2(위치 공격, 2일) → F3(스킬 연결, 2일)
F4(약점 표기, 1일)·F5(스트레스·도주, 2일)는 F1~F3와 독립 — 병행 가능
→ F6(밸런스 일괄, 1~2일)
```

- 커밋 단위: F 항목별 1커밋 (데이터+로직+테스트+로케일 동봉), 각 커밋 green.
- 매 항목: `npm.cmd test` + `node js/data/validate.js` + `check-help-coverage.mjs`.
- 완료 기준은 상위 계획의 종료 게이트 표를 따른다.
