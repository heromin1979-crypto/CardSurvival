## 2. 핵심 발견 (분석 결과 요약)

### 2.1. 최상위 구조 문제: 이중 전투 엔진

모든 개선의 전제가 되는 사실. **두 개의 전투 엔진이 공존하며 실전에서 혼합 동작한다.**

| 구분 | 레거시 엔진 | 랭크 엔진 (DD식) |
|------|------------|------------------|
| 진입점 | `resolveAction()` `CombatSystem.js:1061` | `selectSkill/selectTarget/confirmAction` `CombatSystem.js:298/316/661` |
| 실행 | `_attackAction()` `:1170` (220줄) | `executeSkillCommand()` `CombatSkillSystem.js:368` |
| 계산 정밀도 | 명중+사기+야간+아이덴티티+회피+치명타+약점/저항+방어 차감 | **skill.accuracy 단일 굴림. 치명타·회피·보정 전무** (`CombatSkillSystem.js:398`) |
| 실제 사용처 | **적 턴 전체** (`processUntilAllyTurn` `:735` → `_runSingleEnemyTurn` `:1904`) + 폴백 UI | **플레이어/동료 턴** (정상 전투는 항상 랭크 UI: `CombatUI.js:1141` 분기) |

즉 **플레이어 공격은 얕은 계산, 적 공격은 정교한 계산**이라는 비대칭이 존재. HP는 `_syncRankedTargetToLegacy(:622)` / `_syncLegacyAlliesToRankedCombatants(:640)` / `syncCombatantsToGameState(CombatantAdapter.js:86)`로 양방향 수동 동기화 중.

## 4. Track 0 — 전투 엔진 단일화 (선행)

### Goal
정상 전투의 모든 판정이 **랭크 엔진 한 곳**에서 이뤄지고, 레거시 엔진의 정교한 계산(치명타·야간·사기·약점/저항·아이덴티티)이 랭크 파이프라인에 이식된 상태. 미결선 모듈(토큰 소비, 상태이상 틱, 관계 반응)이 실제로 동작.

### 세부 작업
1. **명중/피해 파이프라인 통합**: `CombatSkillSystem.executeSkillCommand(:368)`의 단일 굴림을 단계형 파이프라인으로 교체 — 기본 accuracy → 야간 패널티(`nightAccuracyPenalty`) → 사기 보정(`getMoraleTier().accBonus`) → 아이덴티티(`_applyCharacterAimIdentity :964`) → **dodge 토큰 소비** → 명중 확정 → 치명타 굴림(무기 critChance + critBonus) → 약점/저항(`weaponWeaknessMult/ResistanceMult`) → 방어 차감. 레거시 `_attackAction(:1170)`의 220줄 로직을 함수 단위로 분해해 이식.
2. **토큰 소비 결선**: `CombatStatusSystem`에 명중 판정 시 `dodge` 소비, 피해 계산 시 `strength/power`(가해 증가)·`vulnerable`(피해 증가)·`block`(기존), 타겟팅 시 `taunted` 강제를 결선. 토큰별 배수는 `gameBalance.js` `combat.tokens` 블록으로 신설.
3. **상태이상 틱 결선**: `tickStatusEffects(:260)`를 라운드 경계(`_advanceTurn:800`의 roundNumber 증가 지점)에서 호출. 레거시 `_tickStatusEffects(:2483)`와 이중 발동되지 않도록 적/아군 소유권을 한쪽으로 정리.
4. **적 턴을 랭크 엔진으로 이관**: `_runSingleEnemyTurn(:1904)`이 `_enemyAttack` 대신 랭크 스킬 커맨드를 발행하도록 변경. 레거시의 6종 aiPattern(`_pickTargetByPattern:1791`)과 의도 시스템(`_decideNextIntent:1834`)을 `EnemyCombatAdapter.decideEnemyIntent(:85)`로 승격(현재의 "첫 스킬·첫 대상 고정" 제거). 의도 시스템 이중 계산 해소.

6. **파일 분할**: `CombatSystem.js`(2,879줄)를 800줄 규칙에 맞게 분해 — 턴 큐/페이즈 관리, 적 AI, 승패 해결(전리품·사기)을 `js/systems/combat/` 하위로 이동.
