## Track A — stuck 원인 판별과 해소 (2~3일)

**현황:** `tools/sim/combat/run.mjs`의 드라이버 루프(95~160행)는 4가지 사유로 중단하지만 사유를 기록하지 않는다:
① 피해 스킬 없음(`!dmgSkill` break) ② 사거리 밖 + `useActiveSkillByEffect('move')` 실패 ③ `confirmAction()` 실패(`!result.ok && !result.turnConsumed`) ④ `guard 120` 초과.
중단 시 `gs.combat.active`가 살아 있으면 stuck으로 집계된다.

**작업:**
1. `run.mjs`에 stuck 계측 추가 — 중단 사유 enum(no_skill / move_failed / confirm_failed / guard_exceeded) + 해당 시점 `gs.combat` 스냅샷(라운드, 활성 유닛, 포메이션, 남은 적 랭크) 덤프. `--dump-stuck <dir>` 옵션.
2. DL5 stuck 셀 재현 실행 → 사유별 분류:
   - **게임 버그 의심:** `_validateRankedSkillPosition` 전 대상 불능 + 이동도 불가한 교착(예: 근접 무기 vs 후열 잔존 적 + 전열 이동 칸 봉쇄), `confirmAction` 실패 루프.
   - **드라이버 한계:** 피해 스킬이 아닌 스킬만 남은 상태, 단순 타겟 선택 전략 부재.
3. 게임 버그면 `CombatSystem`(confirmAction / 이동 경로) 수정 + 재현 조건 고정 단위테스트 추가. 드라이버 한계면 run.mjs 드라이버 보강(피해 스킬 부재 시 non-damage 스킬 사용, 이동 불가 시 대기/도주) 후 "드라이버 한계" 리포트 각주 갱신.

**완료 기준:** DL5 전 셀 stuck 0, 또는 잔여 전량이 드라이버 한계로 판명되어 리포트에 사유 기록.

## Track B — 적 AI/인텐트 단일화 (3~4일)

**현황:** 인텐트 이중 구조.
- 레거시: `CombatSystem._decideNextIntent` (134행 진입 시 + 1550행 라운드 갱신) → `enemy._nextIntent`
- 랭크: `CombatSystem` 345행 `pickSkill` + `_pickRankTargetByPattern`(368행, 6패턴) → `pendingIntent`
- UI: `CombatUI.js` 334행 "레거시 `_nextIntent` 우선, 랭크 `pendingIntent` 폴백" 분기

표시된 인텐트와 실제 실행 스킬이 다른 경로에서 결정될 수 있는 구조다.

**작업:**
1. 인텐트 결정을 랭크 파이프라인(`CombatAiTurns.js`) 단일 소스로 통합. 라운드 시작 시 확정된 (스킬, 타겟 패턴)을 인텐트 데이터로 발행하고, 실행 시 동일 결정을 재사용.
2. `_nextIntent`는 제거하거나 표시용 어댑터(아이콘/라벨/카운트다운 변환)로 축소. `CombatUI.js` 334행 폴백 분기 제거.
3. **인텐트 정직성 테스트:** 라운드 시작 시 발행된 인텐트의 스킬 == 해당 턴 실제 실행 스킬 검증 단위테스트. `CombatPhase3_enemyIntent.int.test.js` 갱신.

**완료 기준:** 인텐트 결정 경로 1개, 관련 통합테스트 green, 표시-실행 불일치 테스트 통과.

## Track C — 판정 파이프라인 검증 강화 (2~3일, A·B와 병렬 가능)

**현황:** `CombatResolution.js`(129줄, 순수 함수)에 판정이 모여 있으나 경계 검증 테스트가 얇다.

**작업 (테스트 추가 위주, 동작 변경은 버그 발견 시에만):**
1. 경계 테스트 — 명중률 0/100% 클램프, 토큰 소비 순서(dodge/accuracy/focus)와 1회성 소비, marked(×1.5)·vulnerable 중첩 계산, `defenseFloorRatio 0.30` 하한 (랭크/레거시/프리뷰 3경로 모두).
2. **프리뷰 정직성:** `previewRankedSkill`과 `_resolveRankedHit`가 공용 `_rankedAimProfile`을 쓰는지 수치 일치 테스트 — 스킬 카드 표기(피해/명중%/치명%)가 실제 판정과 어긋나면 즉시 red.
3. 상태이상 라운드 경계: `CombatStatusSystem` + `_onRoundStart` 레거시·랭크 이중 틱 여부 회귀 테스트.

**완료 기준:** 신규 테스트 전부 green, 발견 버그는 개별 커밋 + 회귀 테스트 동반.

## Track D — 밸런스 목표 정렬 (3~4일, A·B 완료 후)

**선행 조건:** Track A·B 반영 후 `--n 100` 재측정으로 기준선 갱신 — stuck·AI 수정만으로 승률이 움직일 수 있다.

**작업:**
1. **DL3 무장 100% → 60~75%:** 조정 소관은 `js/data/enemies.js`의 `rollEnemyGroup`(그룹 크기/구성) — 개별 적 HP·공격(`enemies.js` 데이터)보다 그룹 구성 조정을 우선한다. DL1 90%+가 깨지지 않는지 동시 확인.
2. **평균 라운드 1.4~2.5 → 4~7:** 그룹 크기 상향과 연동해 자연 상승 예상. 부족하면 적 HP 소폭 상향(gameBalance가 아닌 enemies 데이터).
3. **약탈자 2인조 vs 권총·칼 13% 이상치:** A·B 수정 후 재측정 먼저. 잔존 시 원거리 이동 턴 소모(진형 시작 거리)와 defensive AI의 원거리 우선 타겟 로직(`_pickRankTargetByPattern`) 개별 검토.
4. **시뮬 축 확장:** `run.mjs`에 방어구/동료 축 추가(현재 하한선 전용) — 최소 (무방어구/기본 방어구) × (단독/동료 1) 매트릭스. DL5 40~60% 목표는 실플레이 조건(방어구+동료) 기준으로 판정.
5. 절차: 변경 → `--n 100` 스팟 → 목표 근접 시 `--n 300` 확인 → 최종 `--n 1000` 확정 리포트 커밋.

**완료 기준:** 목표 표의 승률·라운드 달성, `COMBAT_SIM_REPORT.md` n≥1000 갱신 커밋, 기준선 대비 변화를 `BASELINE_2026-07-13.md`에 비교표로 추가.

## Track E — 구조 부채 정리 (선택, Phase 2 말미 여유 시)

- `CombatSystem.js` 2,166줄 / `CombatAiTurns.js` 1,169줄 / `CombatUI.js` 1,498줄 — 800줄 규칙 초과. **밸런스 작업과 동시 분할 금지**(마스터플랜 보류 사유 유지). D 완료·전 테스트 green 후 기계적 분할만 수행.
- `RelationshipCombatSystem.js`(201줄) 결선 여부 결정 — 미결선이면 보류 사유 재확인 후 명시.
- `CombatActions.js`의 deprecated `companionAttack/Heal`(181행~) — 랭크 경로 안정 확인 후 레거시 폴백 제거 가능 여부 판단.
