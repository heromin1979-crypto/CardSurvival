# Phase 4 — UI/플로우 개선 (1.5~2주)

**진단:** 퀘스트 데이터·알림 coalescing·제작 프리뷰는 이미 구현돼 있다. 부족한 것은 ①상시 노출(트래커) ②우선순위 ③비교/힌트 연결.

### 4-1. 상시 퀘스트 트래커 (3일) — 핵심

- 현황: `QuestPanel`(js/ui/QuestPanel.js, 198줄)이 목표 텍스트(`actionHint ?? desc`)·진행도·subObjective 체크리스트·위치 힌트·D-day까지 전부 렌더하지만 **모달 안에만 마운트**(Basecamp.js:233-242) — 목표를 보려면 매번 📋 버튼.
- 작업: 사이드바(Basecamp.js:112-185, 문자열 조립이라 블록 추가 용이)에 `.bc-section-label` 패턴으로 **"🎯 현재 목표" 섹션 신설** — 활성 퀘스트 1~2개의 한 줄 목표 + 진행도(n/m) + 클릭 시 기존 퀘스트 모달 오픈. QuestPanel의 `_objectiveProgress`(:146)·`_daysLeft`(:183) 로직을 공용 헬퍼로 추출해 재사용(중복 구현 금지).
- 갱신: 모달과 달리 상시 구독 필요 — `mainQuestActivated/subObjectiveCompleted/questListChanged` 구독을 Basecamp 마운트 수명에 묶고 재진입 중복 구독 가드.
- 색: 신규 토큰 없이 `--accent-primary` + `--msg-quest-new`(variables.css:100-108) 재사용 (DESIGN.md 이탈 없음).

### 4-2. 알림 우선순위 + 타입 표준화 (2일)

- 현황: `main.js _initNotifications`(:262)에 coalescing·4장 상한·오버플로가 이미 있으나 **danger가 info와 같은 스택에서 밀려 조기 제거**될 수 있고, 발행 324곳의 `type` 문자열이 `TYPE_MAP`(:276-287) 미등록 시 전부 info 폴백 (예: QuestSystem `type:'story'` :449).
- 작업: ① danger/error는 별도 우선 슬롯(상한 계산 제외 + 수명 연장) ② `TYPE_MAP` 전수 감사 — 발행처 type 목록 추출 스크립트로 미등록 타입 등록 ③ `_initNotifications`를 `js/ui/NotificationCenter.js`로 추출(현재 main.js 내 클로저 — 테스트 불가 구조 해소). 시그니처 정규식(:291-301)은 데이터 상수로.
- 테스트: danger 밀림 방지, story 타입 매핑, coalesce 회귀.

### 4-3. 제작 결과 "장착 대비" 비교 (2일)

- 현황: `CraftUI._renderOutputPreview`(:276-326)는 결과 절대 스탯만 표시 — 현재 장착 무기/방어구 대비 증감 없음.
- 작업: 결과가 weapon/armor면 `GameState.player.equipped`의 해당 슬롯 def와 비교해 `+3▲/-2▼` 병기. 소비품은 비교 없음(절대값 유지). EquipmentModal 로직 재사용 검토 — 없으면 순수 비교 헬퍼 신설 + 단위테스트.

### 4-4. 재료·아이템 획득처 힌트 (2일, Phase 5의 역인덱스에 의존)

- 현황: unmet 재료(:177-185)에 "어디서 얻는지" 안내 전무. 아이템 카드(CardFactory.js) 소스 힌트는 환경 태그 4종뿐(:1219-1223).
- 작업: Phase 5-1의 아이템 공급원 역인덱스를 **빌드타임 산출물(JSON)** 로 생성 → CraftUI unmet 재료에 "획득: 마포구 탐색 / 좀비 무리 드랍" 1줄 표시. 상위 2개 공급원만(정보 과잉 방지). ko/en 등록.
- 순서 주의: 5-1 완료 후 착수 (또는 Phase 5를 먼저 실행).

### 4-5. HeaderBar↔사이드바 중복 정리 (1일)

- 현황: day/time/temp가 HeaderBar(js/ui/HeaderBar.js:5-6 "다음 트랙에서 정리 예정" 주석)와 사이드바(Basecamp.js:102-121)에 이중 표시.
- 작업: 사이드바 쪽 축소(4-1 트래커 공간 확보), HeaderBar 단일 소스화.

### 4-6. DESIGN.md 정밀 검수 (Phase 1 이관, 1일)

- 전투/보드/모달 화면을 DESIGN.md 기준(웜/콜드 이분법, JetBrains Mono, 간격 토큰)과 대조 — 이탈 목록화 후 수정 또는 승인 기록.

**게이트:** 트래커 상시 노출 E2E, danger 밀림 방지 테스트, 비교 표기 단위테스트, 테스트 green + validate 0 + i18n 패리티, UI 기준선 스크린샷 갱신(전투 외 보드 화면 추가).
