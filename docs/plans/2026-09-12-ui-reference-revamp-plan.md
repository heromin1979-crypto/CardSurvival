# 샘플 기반 4개 화면 UI 개선 계획

작성일: 2026-09-12  
상태: 사용자 진행 요청에 따라 4개 화면 UI 개편 적용 및 아래 검증 완료. 장비 전후 비교·프리셋은 별도 기능 범위.

**[!IMPORTANT]**
1. 현재 상태는 직접 읽은 코드와 날짜가 명시된 저장 캡처를 구분해 기술한다.
2. 구현 위치는 실제 파일·함수 기준이다. 제안하는 신규 기능은 기존 기능과 구분한다.
3. 구현 시 실제 코드와 CSS 적용 순서를 다시 확인한다. 이 문서는 코드 복사본이 아닌 변경 설계다.

## 1. 목표와 범위

메인 화면, 장비/인벤토리, NPC 대화, 전투를 **폐허가 된 서울의 생존 장비와 기록물**이라는 하나의 시각 언어로 통일한다. 사용자가 준 이미지의 공간 배치, 인물 비중, 정보 위계를 참고하되 게임 상태와 상호작용은 실제 시스템에 연결한다.

이번 기준 원본:

- `C:/Users/USER/Downloads/카드서바이벌/메인화면00.png`
- `C:/Users/USER/Downloads/카드서바이벌/인벤토리00.png`
- `C:/Users/USER/Downloads/카드서바이벌/대화씬.png`
- `C:/Users/USER/Downloads/카드서바이벌/전투03.png`

이미지 속 문구·능력치·장비명·인원수는 기능 명세가 아니다. 깨진 영문, 중복 장비 슬롯, 의미가 불명확한 숫자는 복제하지 않는다. 전투는 기존 `docs/loop/reference/ui-refs/combat.png`보다 이번 `전투03.png`를 우선한다.

기존 `docs/loop`의 다른 화면 제외 지시는 과거 라운드 범위다. 이번 요청은 네 화면의 계획이며, 과거 라운드의 운영 지시를 실행하거나 범위를 메인 화면으로 축소하지 않는다.

## 2. 접근 방식

| 방식 | 장점 | 비용/한계 |
|---|---|---|
| 표면 스타일만 수정 | 변화 범위가 작음 | NPC 대화의 정보 나열, 장비의 인물 부재까지 해결하기 어려움 |
| **기존 시스템을 활용한 화면별 재구성 — 권장** | 샘플의 구도와 실제 조작을 함께 반영 | 화면별 DOM 정리와 아트 자산 검수가 필요 |
| 샘플의 기능까지 전부 재현 | 이미지와 구성상 가장 가까움 | 장비 프리셋·능력치·전투 규칙까지 범위가 커짐 |

권장안은 공통 스타일을 먼저 확정하고 메인 → 장비 → NPC 대화 → 전투 순서로 적용한다. 전투는 기존 기능이 많아 마지막에 상태별 검증을 집중한다.

## 3. 확인된 구현과 시각적 차이

| 화면/공통 | 확인한 실제 구현 | 개선 초점 |
|---|---|---|
| 메인 | `js/ui/BoardRenderer.js`의 `ROW_CONFIG`는 장소/바닥/휴대 3영역, 장소 9슬롯. `BOTTOM_DISPLAY_CELLS = 9`이며 휴대 페이지를 표시한다. `HeaderBar.render()`가 중앙 날짜/시각/온도를 표시한다. | 기존 영역을 유지하고 배경 노출, 카드 이미지 비중, 섹션 간격, 사이드바 위계를 조정 |
| 장비 | `EquipmentModal._render()`에 상태/장비 탭, 장비에는 효과/캐릭터/인벤토리 3열이 있다. `_renderCharPanel()`은 인물 이모지, `_buildInvRow()`는 아이콘과 텍스트 목록이다. | 전신 이미지와 양옆 슬롯, 이미지 그리드, 선택 장비 상세를 중심으로 개선 |
| NPC | `NPCDialogueModal.show(npcId)`가 공용 `modal-overlay`/`modal-box`에 아이콘·대사·의뢰·거래·동료 기능을 함께 출력한다. | 장면 배경+인물+선택지 구조로 재배치하고 기능 상세는 선택 후 노출 |
| 전투 | `CombatUI._renderInternal()`은 `combatants`/`formations`가 있으면 `_renderFocusedInternal()`로 분기한다. 진형, 행동 순서, 상태 패널, 스킬 카드, 수동 동료 턴이 있다. | 기존 다인 전투의 무대 비율, 인물 크기, 상태/행동 카드 위계 조정 |
| 디자인 | `DESIGN.md`는 카드 110×150, 간격 16/24를 기록하지만 `variables.css`는 카드 141×155, 간격 20/32다. | 문서와 실제 값의 차이를 정리한 뒤 화면별 치수 확정 |

2026-09-07 저장 캡처에서는 메인의 어두운 패널과 조밀한 카드 정보, 장비의 작은 모달과 인물 이모지를 확인했다. 단, 그 메인 캡처는 휴대 2행이고 현재 코드는 9셀 1행이므로 **최신 실행 화면의 증거로 사용하지 않는다.** 대화·전투도 이번 작업에서 라이브 화면 검증은 수행하지 않았다.

과거 레퍼런스 README의 “현재 전투는 1대1” 설명은 지금의 `CombatUI` 분기와 맞지 않는다. 이 설명을 근거로 전투 시스템 신규 개발을 계획하지 않는다.

## 4. 공통 시각 기준

- **배경:** 저채도 청회색 폐허. 카드/글자 아래에는 어두운 면을 확보하고, 패널 사이에서 건물과 공간 깊이가 읽히게 한다.
- **패널:** 무광 금속/그을린 종이 질감, 얇은 테두리, 절제된 코너 표시. 샘플의 강한 금빛 장식은 선택·활성 행동에 한정한다.
- **색상:** `--accent-primary: #c8a060`, 기존 위험/정상/정보 토큰과 전투 진영 토큰을 유지한다. 샘플의 청록 네온·보라 등급을 그대로 추가하지 않는다.
- **텍스트:** 현재 폰트 체계를 유지한다. 한글 제목 → 핵심 수치 → 보조 라벨 순서. 본문과 필수 수치는 기존 14px 이상 기준을 적용하고, 축소 화면의 실제 읽기 가능성도 검사한다.
- **카드:** 이름/이미지/핵심 수치의 고정 영역을 정한다. 수량은 한 위치, 내구는 동일한 푸터 위치에 표시한다. 장착 상태는 등급 테두리와 별도 배지로 구분한다.
- **상태:** 기본·hover·키보드 focus·선택·장착·비활성·위험 상태를 구분한다. 색만으로 구별하지 않고 아이콘/라벨을 병행한다.
- **모션:** 기존 120/220/400ms 체계를 사용한다. 반복 글리치와 전면 스캔라인은 기본 적용하지 않는다. 감소된 모션 설정에서 상태를 알아볼 수 있어야 한다.
- **구현:** `index.html`의 스타일 로드 순서와 마지막 `ui-overrides.css`를 포함해 충돌을 확인한다. 파일 끝에 보정 CSS를 계속 쌓지 않고 해당 컴포넌트의 기존 규칙을 정리한다.

`DESIGN.md`에서 벗어나는 폰트·의미 색상·기본 카드 치수 변경은 확정안에 별도 표시한다. 현재 계획은 기존 기준 안에서 샘플을 해석하며, 가이드 개정은 구현 전 검토 항목이다.

## 5. 메인 화면

### 목표 구성

좌측 생존 HUD / 중앙 장소·바닥·휴대 / 우측 동료 및 동료 상태. 상단 중앙은 날짜·시각·온도에 집중한다.

1. 현재 3영역과 페이지 기능을 보존하고 샘플처럼 영역별 제목 띠와 패널 여백을 명확히 한다. 이미지의 카드 수에 맞춰 실제 소지 용량을 줄이지 않는다.
2. 장소는 풍경 이미지와 장소명이 먼저 읽히게 하고, 위험·요구 비용·출입 상태는 코너/푸터에 정렬한다. 중복 설명은 상세 보기로 옮긴다.
3. 바닥/휴대 카드의 이미지 크롭·수량·내구·장착 배지 위치를 통일한다. 장착/선택/등급 강조가 서로 덮이지 않게 한다.
4. 좌측 지도, 생존 수치, 소음, 무게, 퀘스트를 일정한 제목/구분선/게이지 규칙으로 정리한다. 상단과 사이드바의 시간 중복은 현재 사용 흐름 확인 후 비중을 조정한다.
5. 동료 초상화와 HP를 우선하고 장비·스킬·사기·유대는 아래로 묶는다. 동료 없음 상태도 같은 패널 구조를 유지한다.

대상: `js/ui/BoardRenderer.js`, `js/ui/CardFactory.js`와 `getCardImage()`, `js/ui/HeaderBar.js`, `js/ui/StatRenderer.js`, `js/ui/CompanionPanel.js`, `js/ui/components/Gauge.js`, `css/board.css`, `css/cards.css`, `css/header.css`, `css/layout.css`, `css/screens-game.css`, `css/companion-panel.css`.

완료 기준: 페이지 마지막 카드까지 접근 가능, 드래그/스택/장착 동작 유지, 장소 이동 후 라벨 갱신, 낮/밤과 빈 보드/가득 찬 보드에서 필수 정보 겹침 없음.

## 6. 인벤토리·장비 화면

### 목표 구성

좌측 효과 요약 / 중앙 큰 캐릭터와 양옆 장비 슬롯 / 우측 아이템 그리드와 선택 상세. 기존 캐릭터 상태 탭은 유지한다.

1. `_renderCharPanel()`을 전신 이미지 중심으로 바꾸고 `_renderSlot()`의 실제 슬롯을 양옆에 배치한다. 샘플의 중복 몸/손 슬롯은 만들지 않는다. `SLOT_META`, 실제 장착 가능 슬롯, 저장 상태가 일치하는지 먼저 확인한다.
2. `_renderInvPanel()`·`_buildInvRow()`를 이미지 그리드로 바꾼다. `getCardImage()`를 재사용하고 이미지가 없을 때의 대체 표시를 제공한다. 수량·내구·장착 배지를 유지한다.
3. `_selectedId`를 사용해 선택 상세와 장착 가능한 슬롯을 동시에 강조한다. ‘아이템 선택 → 대상 슬롯/비교 확인 → 장착’ 흐름을 명확히 한다.
4. 효과 목록은 현재 `_getEffects()`가 호출하는 `StatSystem.getArmorEffects()`의 실제 피해 감소·방사선·오염·감염 등으로 구성한다. 샘플의 ‘생존력 +12’ 같은 합성 수치를 만들지 않는다.
5. **장착 전후 비교는 추가 작업**이다. `EquipmentModal`·`EquipmentSystem`에는 비교/프리셋 경로를 확인하지 못했다. `StatSystem`의 집계와 장착 부작용을 더 읽은 뒤, 실제 장착 없이 결과를 계산하는 경로를 설계한다. 미리보기 중 GameState·보드·이벤트를 변경하지 않는다.
6. 샘플의 전투/탐색/휴식 프리셋은 별도 기능 단계로 둔다. 도입 시 저장 포맷, 분실 장비, 슬롯 충돌, 가방 용량 감소, 불완전 세트 처리까지 정의해야 한다.

대상: `js/ui/EquipmentModal.js`의 `_renderEffectsPanel()`, `_renderCharPanel()`, `_renderSlot()`, `_renderInvPanel()`, `_buildInvRow()`, `_bindSlotEvents()`, `_bindInvEvents()`; `css/equipment.css`. 비교 단계에서는 `js/systems/EquipmentSystem.js`, `js/systems/StatSystem.js` 추가 분석.

전신 이미지는 초기에 캐릭터를 나타내는 정적 이미지로 제공한다. 실제 장비 교체마다 복장이 바뀌는 합성/애니메이션은 별도 아트 시스템 범위다.

완료 기준: 모든 유효 슬롯 접근, 장착/해제 및 가방 용량 처리 유지, 빈 필터 상태, 동일 아이템 여러 인스턴스 구별, 긴 이름/수량 표시, 비교 미리보기의 무상태 변경 검증.

## 7. NPC 대화 씬

### 목표 구성

왼쪽 약 2/3는 장소와 인물, 오른쪽 약 1/3는 이름·짧은 대사·선택지. 대사가 있는 게임이므로 샘플의 메뉴만 남기지 않고 읽을 공간을 확보한다.

1. 공용 모달과 충돌하지 않는 대화 전용 화면 범위를 만들고 `show(npcId)`의 진입 계약은 유지한다.
2. 인물 이미지와 장소 배경을 독립 자산으로 표시한다. NPC ID/장소에 따른 매핑을 확인하고 누락 시 초상/중립 배경으로 대체한다. 의뢰마다 신규 배경을 무조건 제작하지 않는다.
3. 선택지는 실제 기능에 따라 의뢰·정보·거래·동료 관리·떠나기로 묶는다. 기능 없는 메뉴는 표시하지 않으며, 조건 미충족은 구체적 이유를 보여준다.
4. 거래 선택 후 기존 교환 목록과 보유 수량을 펼치고, 의뢰 선택 후 목표/진행도를 보여준다. 치료·파견·영입·해제·개인 서사 기능은 해당 NPC의 조건에 맞게 유지한다.
5. 현재 `show()`는 `NPCSystem.talkTo()`를 호출하고 거래 후에도 다시 `show()`를 호출한다. 선택 메뉴를 늘리기 전에 진입 동작과 순수 화면 갱신을 분리할 필요를 검토한다. 실제 시스템 동작을 읽기 전 친밀도 변경 버그라고 단정하지 않는다.
6. `_close()`와 `GameState.ui.modalOpen`, 공용 모달 복구, 선택 후 복귀, Escape/포커스 이동을 함께 정리한다. 강제 선택 딜레마의 닫기 규칙은 일반 대화와 구분한다.

대상: `js/ui/NPCDialogueModal.js`의 `show()`, `_bindEvents()`, `_close()`; `js/systems/NPCSystem.js`, `js/systems/NPCQuestSystem.js`; `css/npc-panel.css`, 관련 공용 모달 CSS. 필요 시 **신규** `css/npc-dialogue.css`와 전용 자산 매핑 파일을 추가한다.

완료 기준: 거래 가능/불가, 영입 전/후, 부상/치료, 진행 의뢰, 긴 대사, 이미지 누락, 연속 열기/닫기에서 기능과 모달 상태 유지. 대화 UI 탐색만으로 의도하지 않은 게임 상태 변화가 발생하지 않는다.

## 8. 전투 화면

### 목표 구성

상단 행동 순서·라운드·지역 정보 / 중앙 아군과 적 무대 / 캐릭터별 상태 패널 / 하단 행동 카드. 샘플의 큰 캐릭터와 낮은 시점의 거리감을 활용한다.

1. `_renderFocusedInternal()`을 기준으로 레이아웃을 다듬는다. `_renderFormationSide()`가 실제 진형/인원수로 배치하며, 샘플처럼 3명으로 고정하지 않는다. 기존 코드의 1~4 rank 표시 의미도 유지한다.
2. `_renderInitiativeBar()`·`_renderTopHud()`에서 현재 행동자와 다음 순서를 구분한다. 라운드 숫자와 다른 비용 숫자가 혼동되지 않게 라벨을 붙인다.
3. `_renderCombatant()`·`_renderStatusPanels()`의 인물, 선택 영역, 상태 패널 연결을 강화한다. 적 의도와 유효 타깃은 배경보다 강한 대비로 표시한다.
4. `_renderSkillBar()`의 이름/그림/피해/명중/비용 위치를 통일한다. 현재 비용은 `skill.costs.stamina`를 읽으므로 샘플의 ‘TP’를 임의로 붙이지 않는다. 탄약·재장전·쿨다운·위치 제한은 기존 판정을 사용한다.
5. 선택/사용 가능/사용 불가를 구분하고 불가 이유를 카드에서 읽게 한다. 아이템·이동·도주 및 수동 동료 턴의 명령 구성을 유지한다.
6. 샘플의 ‘턴 종료’ 버튼은 실제 턴 진행 계약을 추가 확인한 뒤 채택 여부를 결정한다. UI를 맞추기 위해 새로운 턴 규칙을 도입하지 않는다.
7. `js/data/combatAssets.js`·`js/ui/combat/combatUiAssets.js`와 기존 스프라이트/모션을 우선 활용한다. 크기/바닥선/잘림을 조정하되 전투 애니메이션 재제작은 별도 범위다.

대상: `js/ui/CombatUI.js`, `css/screens-combat.css`, 위 자산 매핑. 전투 규칙 변경 필요가 발견되면 시각 변경에서 분리한다.

완료 기준: 플레이어/동료 턴, 적 행동, 타깃 선택/취소, 위치 제한, 탄약 부족/재장전, 사망/빈 진형, 승리/패배/도주에서 상태와 입력이 일치한다. 기존 전투 E2E를 함께 검증한다.
