## 2. 안건 1 — M4 트랙 정체성 정의 ★ 결정

### 2.1 결정 단언

> **M4 트랙은 "시뮬-본체 격차 측정 트랙"이다.** drift.mjs leaf hash + 텔레메트리로 시뮬과 본체의 K1 차이를 측정한다. 시뮬 R11-1 완전 해소 단언(M3 §11.4)의 신뢰도 검증이 본질.

### 2.2 근거

- §15 단정 ("M4+ 텔레메트리 트랙으로 분리")의 자연스러운 후속
- 시뮬 R11-1 완전 해소 단언의 신뢰도 검증
- drift.mjs leaf hash 컬럼 (협의서 v4 §13.6 단정) 동반 권고와 정합
- M3 산출물 (시뮬 K1·K3·K5 마지노선) 재활용 최대화

### 2.3 채택되지 않은 후보

- **후보 B** (게임 본체 K1 직접 측정): 시뮬 분리로 M3 산출물 재활용도 낮음. 격차 측정이 더 본질적
- **후보 C** (직업별 본체 학습곡선): 사용자 데이터 축적 시간 비용. M4 1차 마감 범위 밖
- **후보 D** (혼합): 범위 모호. 마감 정의 어려움

## 3. 안건 2 — 신규 페르소나 영역 정의 ★ 결정

### 3.1 결정 단언

> **시스템 백승호 확장.** 시뮬 로직 책임자가 본체 텔레메트리 수집 채널도 책임진다. 신규 페르소나 정의 작업 회피로 M4 진입 가속.

### 3.2 백승호 확장 책임 범위

| 범위 | 산출물 | 비고 |
|------|--------|------|
| 시뮬 로직 (기존) | playerAI.mjs · 5곳 등록 룰 유지 | M3 §16.3 단정 그대로 |
| 본체 텔레메트리 수집 | `EventBus.on('*')` 후크 + 로컬 JSON 저장 | 신규 (M4 #1) |
| drift.mjs 확장 | leaf hash 컬럼 추가 | 신규 (M4 #2) |
| 본체 K1 측정 | 베타 1회차 + 보고서 | 신규 (M4 #3) |
| 격차 K_sim_drift 단정 | PD 김재훈 공동 단언 | 신규 (M4 #4) |

### 3.3 근거

- 시뮬 로직 책임자가 본체 텔레메트리도 책임지면 시뮬-본체 격차 측정 정합도 ↑
- 신규 페르소나 정의 작업 회피 (M4 진입 가속)
- 백승호의 시뮬 정합 5곳 등록 룰 (협의서 v5 §16.3) 노하우 재활용

### 3.4 채택되지 않은 옵션

- **옵션 α** (텔레메트리 PD 신설): 페르소나 정의 작업 부담
- **옵션 γ** (밸런스 권지나 확장): 시뮬 편향 우려로 본체 측정 객관성 ↓
- **옵션 δ** (PD 김재훈 직속): 협의·우선순위 작업과 충돌

## 4. 안건 3 — M4 KPI 정의 ★ 결정

### 4.1 결정 단언

> **최소 3 KPI 채택.** 본체 K1 / 시뮬-본체 격차 K_sim_drift / drift.mjs leaf hash. 본체 K3·KPI Δ는 측정 인프라 안착 후 M4+ 보강.

### 4.2 채택 KPI 명세

| KPI | 정의 | 마지노선 | 측정 시점 |
|-----|------|---------|----------|
| **본체 K1** | 실제 player 100일 생존율 (직업별 6직업) | 시뮬 K1 ± 10%p | 베타 테스트 N회차 누적 |
| **K_sim_drift** | `|본체 K1 - 시뮬 K1|` (직업별) | ≤ 10%p | 텔레메트리 N회차 누적 |
| **drift.mjs leaf hash** | game data leaf 값 hash 컬럼 추가 | M3 v3~v14 fingerprint 12연속 유지 + M4 무회귀 | 매 baseline 측정 |

### 4.3 후순위 (M4+ 보강)

- 본체 K3 (평균 사망일) — 측정 인프라 안착 후
- 본체 KPI Δ (추세 일치) — N≥3 측정 후 추세 분석 가능 시점

### 4.4 근거

- 본체 K3·KPI Δ는 측정 인프라 안착 후 보강
- M3와 같은 14회 측정 가속화 불가능 (실제 player 행동은 시뮬보다 시간 비용 큼)
- 최소 3 KPI로 M4 진입 가속, 추가 KPI는 인프라 안착 후 단계적 확장

## 5. 안건 4 — M4 측정 인프라 결정 ★ 결정

### 5.1 결정 단언

> **로컬 이벤트 로그.** `EventBus.on('*')` 후크 + 로컬 JSON 저장. 사용자 자발 제출. 개인정보·백엔드 추가 회피.

### 5.2 인프라 명세

| 항목 | 값 |
|------|----|
| 수단 | `EventBus.on('*', telemetryCollector)` |
| 저장 위치 | 로컬 JSON 파일 (`telemetry/{userId}/{sessionId}.json`) |
| 수집 채널 | 핵심 이벤트만 — death / dayEnd / skillLevelUp / itemConsumed / npcRecruit |
| 익명화 | userId는 로컬 UUID, 외부 송신 없음 |
| 사용자 제출 | 자발 (게임 종료 시 export 버튼 제공) |
| 작업량 추정 | 소~중 (~300줄, 시뮬 EventBus 구조 활용) |

### 5.3 근거

- 개인정보 영역 회피 (협의 부담 ↓)
- 사용자 자발 제출 (블랙 박스 회피)
- 시스템 백승호 작업 범위 내 (시뮬과 동일 EventBus 구조 활용)
- M3 §15 단정과 정합 (시뮬-본체 분리 트랙)
- 백엔드 인프라 추가 없음 (정적 사이트 호스팅 그대로)

### 5.4 채택되지 않은 후보

- **후보 ii** (익명 서버 송신): 개인정보 협의 부담 + 백엔드 인프라 추가
- **후보 iii** (디버그 콘솔 export): 자동화 불가
- **후보 iv** (텔레메트리 비활성): KPI 측정 자체 불가 — 트랙 본질 무력화
