# STATUS — 어디까지 했고 다음은 뭔가

> 한 바퀴마다 갱신한다. 루프의 유일한 기억이다.
> "다음에 할 것"이 비면 다음 바퀴는 이어받을 자리를 모른다. 반드시 채운다.

## 지금 상태

루프 뼈대(`loop/ctl.ps1`, `loop/loop.ps1`, `loop/env.ps1`, `loop/PROMPT.md`)와 문서 3종
(`docs/DESIGN.md`, `docs/STATUS.md`, `docs/feedback/INBOX.md`)이 만들어져 있다. 스크립트는 읽었고
내용상 동작 가능한 상태다. 그러나 **판단 근거가 되는 문서 3종이 전부 빈 템플릿**이다 —
`PROMPT.md` ① 합격 기준 공란, ③ 규칙 표 공란, `DESIGN.md` 1~7절 전부 공란,
`INBOX.md` "처리할 것" 공란. 규칙 ④에 따르면 이번 바퀴의 작업은 INBOX 또는 STATUS "다음에 할 것"에서
나와야 하는데 양쪽 다 비어 있어, **작업을 고를 수 없다.** 아직 루프가 만든 산출물은 없다.

## 막힌 것

<!-- 사람이 풀어줘야 하는 것. 루프는 여기를 건드리지 말고 넘어간다. -->

1. **목표가 어디에도 적혀 있지 않다.** 아래 중 최소 하나를 사람이 채워야 루프가 일을 시작할 수 있다.
   - `loop/PROMPT.md` ① 합격 기준 (한 문장) — 무엇이 되면 끝인가
   - `docs/DESIGN.md` 1절(한 줄 정의) · 2절(만드는 것) · 3절(만들지 않는 것)
   - `docs/feedback/INBOX.md` "처리할 것" — 당장 시킬 지시 한 줄
   셋 다 비어 있는 한 다음 바퀴도 같은 이유로 아무것도 만들지 못한다.

2. **현재 설정으로는 루프가 커밋도 테스트도 하지 못한다.** `loop/env.ps1:26`의
   `$LOOP_PERMISSION_MODE = 'acceptEdits'`는 파일 편집만 자동 승인하고 셸 명령은 승인을 요구한다.
   헤드리스에는 승인할 사람이 없으므로 `npm test`와 `git commit`이 거부된다 — env.ps1 주석(19~24행)이
   이 사실을 직접 적어 두었다. 규칙 ⑤(검사 통과 후 즉시 커밋)와 ⑥(실행해서 확인)을 지키려면
   `bypassPermissions`로 바꿔야 하는데, 이는 무인 세션에 셸 전권을 주는 결정이라 사람이 정할 몫이다.

3. **관찰** — `loop/env.ps1:10`의 `$LOOP_MAX_TURNS = 6`은 ②의 문서를 읽는 데만 3~4턴이 든다.
   실제 코드 작업 + 실행 확인 + 커밋 + STATUS 갱신까지 한 바퀴에 담기에는 부족할 수 있다.
   막힌 것은 아니지만, 바퀴가 계속 중간에 끊기면 이 값을 먼저 의심한다.
