# 전투 시스템 기획 정리

> 현재 구현 기준: `js/systems/CombatSystem.js`, `js/systems/CombatActions.js`, `js/ui/CombatUI.js`, `css/screens-combat.css`, `js/data/gameBalance.js`, `js/data/enemies.js`

## 1. 전투의 목표

현재 전투는 카드 생존 게임 안에서 “탐사 중 위험을 만났을 때 짧고 명확하게 결판을 내는 전술 전투”로 설계되어 있다.

플레이어가 매 전투에서 판단해야 하는 핵심은 다음 네 가지다.

1. 지금 공격할지, 방어할지, 이동할지, 도망칠지 결정한다.
2. 앞열과 후열 규칙에 따라 어떤 적을 먼저 처리할지 선택한다.
3. 동료 NPC를 자동 행동으로 둘지, 수동 명령으로 직접 운용할지 정한다.
4. 적의 다음 행동 의도를 보고 피해를 줄이거나 우선 처치 대상을 정한다.

전투는 실시간 액션이 아니라 턴 기반이다. 다만 화면 표현은 다키스트 던전처럼 캐릭터와 적이 좌우로 마주 보고, 공격 시 일정 거리 앞으로 나갔다가 타격하는 방식으로 보이도록 구성되어 있다.

## 2. 전투 진입 흐름

전투는 상태 전환이 `combat`으로 들어올 때 시작된다.

- 호출 위치: `CombatSystem.init()`의 `stateTransition` 이벤트
- 초기화 함수: `CombatSystem._setupCombat(data)`
- 전투 상태 저장 위치: `GameState.combat`

전투 시작 시 결정되는 항목은 다음과 같다.

| 항목 | 설명 |
| --- | --- |
| 적 목록 | 전달받은 `data.enemies`가 있으면 사용하고, 없으면 위험도와 소음 기반으로 적 그룹을 생성한다. |
| 위험도 | `data.dangerLevel`, 없으면 기본값 2를 사용한다. |
| 전투 로그 | 일반 전투, 호드 웨이브, 약탈자 습격 여부에 따라 시작 문구가 달라진다. |
| 플레이어 위치 | `playerRank`가 없으면 기본 전열이다. |
| 턴 큐 | 플레이어, 살아있는 동료, 적을 모아 행동 우선순위로 정렬한다. |
| 적 의도 | 모든 적은 전투 시작 시 다음 행동 의도 `_nextIntent`를 미리 계산한다. |
| 연출 큐 | `fxQueue`에 전투 연출 이벤트가 쌓이고, UI가 순차 재생한다. |

전투 시작 시 캐릭터별 전투 시작 대사가 호출된다.

## 3. 턴 구조와 행동 우선순위

전투는 `turnQueue`라는 순서표로 진행된다.

턴 큐 항목은 세 종류다.

| 타입 | 의미 |
| --- | --- |
| `player` | 플레이어 캐릭터 |
| `companion` | 동료 NPC |
| `enemy` | 적 개체 |

현재 행동 우선순위는 `CombatSystem._initiativeScore()`에서 계산한다.

| 대상 | 우선순위 계산 기준 |
| --- | --- |
| 플레이어 | `actionSpeed`, `speed`, `initiative`가 있으면 우선 사용한다. 없으면 현재 스태미나 비율 기반으로 80~100 사이 점수를 준다. |
| 동료 | 동료 상태의 `actionSpeed`, `speed`, `initiative`가 있으면 우선 사용한다. 없으면 HP 비율 기반으로 65~75 사이 점수를 준다. |
| 적 | 적 데이터의 `actionSpeed`, `speed`, `initiative`가 있으면 우선 사용한다. 없으면 기본 45점에 `attacksPerRound`가 높을수록 가산한다. |

기획적으로 보면 “행동력이 높은 캐릭터가 먼저 행동한다”는 구조가 들어가 있으며, 아직 전용 스탯명이 확정되지 않았기 때문에 여러 필드명을 호환해 받는 상태다.

전투 시작 시에는 조작 가능한 액터가 먼저 잡히도록 보정한다. 즉, 플레이어 또는 수동 조작 동료가 있다면 그 위치에서 입력을 받는다.

## 4. 플레이어 행동

플레이어가 선택할 수 있는 기본 행동은 `CombatSystem.resolveAction()`에서 처리된다.

| 행동 | 내부 action | 설명 |
| --- | --- | --- |
| 공격 | `melee`, `shoot` | 장착 무기 또는 선택 무기로 공격한다. |
| 방어 | `guard` | 다음 피해를 줄이고 반격 보너스를 준비한다. |
| 이동 | `move` | 플레이어 전열/후열을 전환한다. |
| 투척 | `throwable` | 화염병, 폭발물, 도주 아이템 등 투척 효과를 실행한다. |
| 아이템 | `useItem` | 의료 아이템 등 사용 가능한 아이템을 쓴다. |
| 은신 | `stealth` | 성공 시 전투 회피, 실패 시 적 행동을 유발한다. |
| 도주 | `flee` | 기본 60% 확률로 도주한다. 실패 시 적 공격을 받는다. |
| 동행 공격 | `companionAttack` | 기존 보조 버튼. 모든 동료가 한 번에 공격하는 쿨다운형 보조 행동이다. |
| 동행 치료 | `companionHeal` | 기존 보조 버튼. 동료가 플레이어를 치료하는 쿨다운형 보조 행동이다. |

근접 공격은 앞열 규칙을 따른다. 후열 적을 선택했더라도 앞열 생존 적이 있으면 자동으로 공격 가능한 적에게 재조준된다.

원거리 무기는 탄약 요구 조건이 충족되면 후열 적을 직접 공격할 수 있다. 탄약이 없으면 일부 무기는 근접 대체 피해로 처리된다.

## 5. 공격 판정

공격은 `CombatSystem._attackAction()`에서 처리된다.

공격 계산 흐름은 다음과 같다.

1. 사용할 무기 정보를 읽는다.
2. 피해 범위, 명중률, 치명타율, 소음, 내구도 소모를 계산한다.
3. 야간, 사기, 캐릭터 특성, 무기 숙련, 약점/저항을 반영한다.
4. 명중하면 적 HP를 줄이고, 빗나가면 miss 연출만 발생한다.
5. 적이 사망하면 처치 보상과 다음 타겟을 처리한다.
6. 상태이상과 쿨다운을 틱 처리한다.
7. 전투가 끝나지 않았으면 AI 턴으로 넘어간다.

기본 전투 밸런스 값은 `gameBalance.js`의 `combat` 섹션에 있다.

| 값 | 현재 의미 |
| --- | --- |
| `unarmedBaseDmg` | 맨손 기본 피해 |
| `baseUnarmedAccuracy` | 맨손 기본 명중률 |
| `defaultCritMultiplier` | 별도 설정이 없는 치명타 배율 |
| `weaponWeaknessMult` | 약점 속성 피해 배율 |
| `weaponResistanceMult` | 저항 속성 피해 배율 |
| `nightAccuracyPenalty` | 야간 전투 명중 패널티 |
| `enemyDropChance` | 일반 적 드랍 확률 |
| `doctorZombieMedDropChance` | 의사 캐릭터가 좀비 처치 시 의료 아이템 추가 드랍 확률 |

## 6. 전열/후열 규칙

전투는 단순 좌우 배치가 아니라 전열/후열 규칙을 가진다.

적 데이터에는 `row` 또는 `position`이 들어갈 수 있다.

| 위치 | 의미 |
| --- | --- |
| `front` | 전열. 근접 공격으로 직접 공격 가능하다. |
| `back` | 후열. 앞열 적이 살아 있으면 근접 공격으로 직접 공격할 수 없다. |

후열에 있는 근접 적은 자기 턴에 바로 공격하지 않고 전열로 전진한다. 이 행동은 적 의도에서 `advance`로 표시된다.

현재 UI는 살아있는 적만 메인 전장에 배치한다. 앞열 적이 죽으면 후열 적이 시각적으로 앞으로 당겨져 보인다. 단, 내부 타겟 인덱스는 원래 적 배열 인덱스를 유지하므로 타겟 판정은 깨지지 않는다.

## 7. 동료 NPC 행동

동료는 전투 턴 큐에 포함된다.

동료 행동은 `stance`로 제어된다.

| stance | 설명 |
| --- | --- |
| `attack` | 공격 가능한 적 중 HP가 낮은 적을 우선 공격한다. |
| `heal` | 플레이어 HP가 기준 이하이면 치료하고, 아니면 공격으로 대체한다. |
| `support` | 클래스 스킬 쿨다운이 준비되면 사용하고, 아니면 공격으로 대체한다. |
| `hold` | 피해 감소 버프를 준비한다. |
| `manual` | 자동 행동하지 않고 플레이어 명령을 기다린다. |

수동 동료 턴에서는 `CombatSystem.resolveManualCompanionAction()`을 통해 다음 명령을 내릴 수 있다.

| 수동 명령 | 설명 |
| --- | --- |
| 공격 | 현재 동료가 선택 가능한 적을 공격한다. |
| 치료 | 현재 동료가 치료 로직을 실행한다. |
| 대기 | 방어/대기 성격의 `hold` 행동을 실행한다. |

동료 자동 공격 기본값은 `gameBalance.js`의 `companionAuto`에 있다.

| 값 | 의미 |
| --- | --- |
| `attackDamage` | 동료 자동 공격 피해 범위 |
| `attackAccuracy` | 동료 자동 공격 명중률 |
| `healAmount` | 동료 치료량 범위 |
| `healThreshold` | 플레이어 HP가 이 비율보다 낮으면 치료 시도 |
| `holdDamageReduct` | 대기/방어 시 피해 감소율 |
| `rangedCompanions` | 후열을 직접 공격할 수 있는 원거리 동료 목록 |

동료 클래스 스킬은 현재 세 종류가 있다.

| NPC | 스킬 | 효과 |
| --- | --- | --- |
| 간호사 | `nurse_triage` | 아군 전체 회복 |
| 군인 | `soldier_suppress` | 일정 턴 동안 적 공격 약화 |
| 의사 NPC | `doctor_diagnose` | 아군 상태이상 저항 보너스 |

## 8. 적 AI와 의도 표시

적은 자기 턴 직전에 무작위로 행동하는 것이 아니라, 다음 행동 의도 `_nextIntent`를 미리 가진다.

의도는 `CombatSystem._decideNextIntent()`에서 정한다.

의도 종류는 다음과 같다.

| 의도 | 설명 |
| --- | --- |
| `attack` | 플레이어 또는 동료를 공격한다. |
| `skill` | 쿨다운이 준비된 특수 스킬을 사용한다. |
| `advance` | 후열 근접 적이 전열로 이동한다. |
| `timed_threat` | 충전형 위협을 카운트다운한다. |

적 타겟은 AI 패턴과 가능한 대상에 따라 정해진다.

적은 기본적으로 플레이어를 공격하지만, 일정 확률로 동료를 공격할 수 있다. 이 확률은 `companionTargetChance`에서 관리한다.

UI에서는 이 의도를 아이콘과 대상 표시로 노출한다. 기획 의도는 Into the Breach처럼 “적이 다음에 무엇을 할지 미리 보여주고 대응하게 하는 전투”에 가깝다.

## 9. 특수 적과 위협 패턴

일반 적 데이터는 `js/data/enemies.js`, 보스/희귀 적 데이터는 `js/data/secretEnemies.js`에 있다.

적 데이터에서 기획자가 조절할 수 있는 주요 필드는 다음과 같다.

| 필드 | 설명 |
| --- | --- |
| `hp` | 적 체력 범위 |
| `attack.damage` | 공격 피해 범위 |
| `attack.accuracy` | 명중률 |
| `attack.noiseOnAttack` | 공격 시 발생 소음 |
| `defense` | 방어력 |
| `xp` | 처치 경험치 |
| `lootTable` | 처치 보상 후보 |
| `infectionChance` | 감염 위험 |
| `aiPattern` | 공격 성향 |
| `attackType` | 근접/원거리 성격 |
| `position` 또는 `row` | 전열/후열 배치 |
| `attacksPerRound` | 한 라운드 공격 횟수 또는 행동력 가산 요소 |
| `specialSkills` | 쿨다운형 특수 스킬 |
| `statusInflict` | 명중 시 부여할 상태이상 |
| `weaknesses` | 약점 무기 속성 |
| `resistances` | 저항 무기 속성 |
| `stealthDifficulty` | 은신 회피 난이도 |

특수 위협은 `timedThreats`로 관리된다.

| 위협 | 기획 의미 |
| --- | --- |
| `bloater` | 일정 턴 뒤 폭발/광역 피해를 주는 적 |
| `screamer` | 일정 턴 뒤 지원 적을 부르는 적 |
| `charger` | 일정 턴 뒤 강한 돌진 공격을 하는 적 |

## 10. 방어, 도주, 은신

방어는 `guardAction()`에서 처리된다.

현재 방어의 기본 역할은 다음과 같다.

- 받는 피해 감소
- 반격 보너스 준비
- 일정 턴 뒤 소모

도주는 `fleeChance`를 기준으로 판정한다.

- 성공: 전투 종료, 피로 증가
- 실패: 적 공격을 받음
- 호드/공성 등 특수 전투에서는 도주 결과가 추가 피해나 패배 처리와 연결될 수 있다.

은신은 살아있는 적들의 `stealthDifficulty` 중 높은 값을 기준으로 성공 여부를 계산한다.

## 11. 상태이상과 지속 효과

상태이상은 플레이어와 적에게 각각 적용된다.

현재 확인되는 구조는 다음과 같다.

| 대상 | 저장 위치 |
| --- | --- |
| 플레이어 상태 | `combat.playerStatus` |
| 현재 타겟 호환 상태 | `combat.enemyStatus` |
| 개별 적 상태 | `enemy._statusEffects` |

상태이상 틱은 `CombatSystem._tickStatusEffects()`에서 처리된다.

기본적으로 매 행동 후 다음 효과가 발생할 수 있다.

- HP 지속 감소
- 감염 수치 변화
- 지속시간 감소
- 동료 쿨다운 감소
- 방어 상태 소모

## 12. 승리와 패배

승리는 모든 적이 사망하면 처리된다.

승리 시 일어나는 일:

- 전투 상태 비활성화
- 결과 `victory` 기록
- 사기/피로 변화
- 전투 보상 지급
- NPC 전투 승리 후처리
- 캐릭터 승리 대사
- 전투 결과 화면으로 이동

패배는 플레이어 HP가 0 이하가 되면 처리된다.

패배 시 일어나는 일:

- 전투 상태 비활성화
- 결과 `defeat` 기록
- 캐릭터 패배 대사
- 관련 이벤트 발행
- 패배/게임오버 흐름으로 이동

인간형 적은 사기(`currentMorale`)가 0 이하가 되면 도주 처리될 수 있다. 도주한 적은 보상 배율이 낮아질 수 있다.

## 13. 전투 UI 표현

전투 UI는 `CombatUI.js`와 `screens-combat.css`가 담당한다.

주요 화면 요소는 다음과 같다.

| UI 요소 | 설명 |
| --- | --- |
| Initiative Bar | 현재 턴 순서와 활성 액터를 보여준다. |
| 전장 라인업 | 왼쪽 아군, 오른쪽 적을 배치한다. |
| 액션 카드 | 공격, 방어, 아이템, 이동, 도주를 선택한다. |
| 보조 액션 줄 | 추가 무기, 투척, 동료 명령, 은신 등을 제공한다. |
| HP 오버레이 | 캐릭터/적 체력과 상태를 보여준다. |
| 의도 아이콘 | 적이 다음에 할 행동을 보여준다. |
| 전투 로그 | 최근 전투 결과를 기록한다. |

현재 캐릭터/적 연출은 스프라이트 시트가 아니라 단일 이미지에 CSS 애니메이션 클래스를 붙이는 방식이다.

연출 이벤트는 `CombatSystem._fx()`로 `fxQueue`에 쌓이고, `CombatUI._playFxQueue()`가 순차 재생한다.

대표 연출:

| 이벤트 | 화면 표현 |
| --- | --- |
| `playerAttack` | 플레이어 전진 + 공격 모션 + 적 피격 |
| `companionAttack` | 동료 전진 + 공격 모션 + 적 피격 |
| `enemyAttack` | 적 전진 + 공격 모션 + 플레이어 피격 |
| `enemyAttackCompanion` | 적 전진 + 동료 피격 |
| `advance` | 후열 적 전열 이동 |
| `guard` | 방어 자세 |
| `useItem` | 회복/버프 펄스 |
| `victory` | 승리 모션 |
| `defeat` | 패배 모션 |

향후 제작된 캐릭터 애니메이션 이미지를 적용하려면 `COMBAT_CHARACTER_MOTION_LIST.md`의 클래스 계약을 유지하면서 CSS 애니메이션을 스프라이트 시트 재생 방식으로 교체하면 된다.

## 14. 현재 시스템의 장점

현재 전투 시스템은 다음 강점을 가진다.

1. 앞열/후열 규칙이 있어 단순 클릭 전투보다 타겟 선택 의미가 있다.
2. 적 의도를 미리 보여주므로 대응형 전투로 확장하기 좋다.
3. 동료가 자동/수동 양쪽으로 운용 가능하다.
4. 적 데이터 필드가 많아 적 개성을 데이터만으로 추가하기 쉽다.
5. 전투 결과가 보상, 감염, 소음, 사기, 피로 등 생존 시스템과 연결된다.
6. CSS 모션 계약이 있어 향후 스프라이트/애니메이션 에셋으로 교체하기 쉽다.

## 15. 현재 보완이 필요한 부분

기획 관점에서 다음 항목은 명확히 결정하면 좋다.

| 항목 | 현재 상태 | 기획 결정 필요 |
| --- | --- | --- |
| 행동력 스탯명 | `actionSpeed`, `speed`, `initiative`를 모두 호환 | 공식 명칭과 캐릭터 스탯 연결 방식 확정 |
| 동료 수동 조작 | 공격/치료/대기 가능 | 동료별 전용 액션 카드가 필요한지 결정 |
| 전열/후열 플레이어 효과 | 플레이어 위치 전환은 있음 | 후열일 때 명중/회피/피해 보정 여부 결정 |
| 적 의도 대응 | 의도 표시와 일부 행동 대응 가능 | 방어/이동/처치 외 추가 대응 행동 설계 |
| 상태이상 UI | 배지와 모션 일부 표시 | 기획자가 읽을 수 있는 상태 설명 툴팁 필요 |
| 전투 난이도 곡선 | 위험도/소음 기반 적 생성 | 지역별, 날짜별, 랜드마크별 전투 테이블 확정 필요 |
| 애니메이션 에셋 | 단일 이미지 + CSS 모션 | 캐릭터별 실제 애니메이션 시트 적용 여부 결정 |

## 17. 한 줄 요약

현재 전투 시스템은 “행동 우선순위 기반 턴제 전투 + 전열/후열 타겟 규칙 + 적 의도 예고 + 동료 자동/수동 운용 + 생존 자원과 연결되는 보상/위험” 구조로 구현되어 있다. 기획적으로는 다키스트 던전식 좌우 전장 표현과 Into the Breach식 의도 예고를 섞은 방향이며, 다음 단계는 행동력 공식과 캐릭터별 애니메이션/전용 스킬을 확정하는 것이다.
