## 3. 의료 감사와 보강 설계

### 현재 구조로 가능한 재미와 한계

가능한 것: 초기 구호품 제작, 진단 도구, 플레이어 부위별 치료(`treatPart`), 질병 진단·태그별 치료(`DiseaseSystem.onConsume`), 의료 구조물 효과, 환자 유입과 완치 후 기여.

부족한 것: 동일한 NPC에게 왜 다른 물품이 필요한지, 중간재를 지금 치료에 쓸지 고급 물품으로 가공할지, 치료 시설이 환자의 회복 단계에 어떤 역할을 하는지. NPC는 `woundLevel`과 지정 치료 아이템 중심이고, 플레이어의 세부 질병/부위 체계와 동일한 경로가 아니다. 플레이어 의료 기능이 NPC에게도 동작한다고 가정하지 않는다.

`sterile_kit`은 야전 수술대의 실제 제작 입력이다. 완전한 미사용 아이템이라고 분류하지 않는다. `surgical_anesthetic`은 추가 가공되지만 조사한 NPC 치료 경로에서 개별 역할을 찾지 못했다. `antibiotic` 태그는 플레이어 여러 질병 치료에 쓰이므로 모든 약품이 단순 HP 물약이라는 진단도 틀리다.

### 최소 치료 단계

새 NPC 치료 상태는 필요한 환자 사례에만 적용한다: 미진단 → 진단 → 안정화 → 처치 → 회복 → 완치. 경상은 진단/안정화만으로 종료 가능. 기존 모든 환자를 6단계로 강제하지 않는다.

| 사례 | 핵심 제작·판단 | 환경의 역할 | 회복 결과 |
|---|---|---|---|
| 초반 부상 군인 | 시작 붕대와 천→천조각→붕대/거즈 사용을 학습 | 시작 의무 거점을 그대로 활용 | 첫 협력자·다음 수급 단서 |
| 탈수·영양 부족 | 깨끗한 물과 회복식, 물품 선택 | 안정적인 휴식·음용수 공급 | 식량/생활 물자 후원 |
| 골절·복합 외상 | 부목/지지대 + 처치 도구 준비 | 침상으로 회복 운영 | 운반·작업 지원 |
| 감염 위험 사례 | 진단 결과에 맞는 의약품과 위생 물품 | 격리·청결 설비가 관리 부담 감소 | 의료 재료 공급 정보 |
| 중증 외상 | 멸균 도구·게임용 마취 소모품·회복 물품을 묶어 준비 | 시술 가능한 장소 요구 | 고급 진료 프로젝트 성취 |
| 연구 사례 | 표본 출처 확인·보관·분석·합성 | 전문 연구 환경 요구 | 기존 연구/백신 분기 |

새 사례 ID 및 수량은 각 구현 작업에서 데이터에 명시하고, 환자별 지정 재료의 이름을 UI에서 읽어 표시한다. 의료 소모품 선택이 되면 검증을 먼저 하고, 실패 시 재료/시간/환자 상태를 전혀 바꾸지 않는다. 진단은 선택 정보를 열고, 오진을 무작위 처벌로 만들지 않는다.

### 재료·설비 체인

- 외상: cloth → cloth_scrap → bandage/gauze → 처치 준비. 상위 키트는 기본 붕대를 완전히 대체하는 만능 정답으로 만들지 않는다.
- 약품: herb → herbal_extract → concentrated_serum → broad_antibiotic. 일반 치료·연구의 두 소비처를 부여한다. 희귀 완제품 antibiotics에 의존하는 부분은 회수/거래/합성 대안을 보장한다.
- 정제: herb_powder → crude_medicine → purified_medicine → synthetic_antibiotics. 수율·시간·설비 차이를 검토하고 같은 치료를 더 비싸게 하는 무의미한 단계는 통합한다.
- 도구: scalpel → sterile_kit → 반복 시술 준비. 도구는 유지하고 거즈·세척 재료·마취 소모품을 쓰는 모델을 검토한다. 이미 건설된 수술대에 도구를 다시 요구해 이중 과금하지 않는다.
- 연구: 일반 infected_blood_sample과 0번 환자의 서사적 표본 출처를 구분한다. 현재 백신은 bossKillId와 doctor 해금 조건이 있으므로 일반 표본 드랍이 곧 보스 게이트 우회라고 단정하지 않는다. 중요 표본을 임의 지역 %로 지급하는 연출의 충돌을 해소한다.
- 현재 환자 24/48TP 타이머는 짧은 붕대 치료용으로 설계돼 있다. 장기 프로젝트 환자에게 그대로 적용하지 않는다. 안정화 시 응급 시계를 종료하고 회복 단계의 다른 규칙으로 이동한다.

## 5. 수급 경제와 지속 탐색

지역별 상세 수정은 별첨의 25구 표를 따른다. 원료 중심으로 바꾸기 전에 필요한 공구·점화·용기·작업대가 가까운 경로에 존재하는지 확인한다. 모든 물품을 맨손부터 만들게 하거나 기존 완제품을 일괄 삭제하지 않는다.

권장 공급 역할:
- 일반 탐색: 반복되는 생활 원료와 분해 대상.
- 특정 장소: 전문 재료와 회수 대상, 제한된 구호 완제품.
- 탐색도: 제작의 병목을 보완하는 고정 묶음과 새 공급처.
- 퀘스트: 다음 공정을 이해하는 단서·필요 도구 접근·관계. 최종 결과물을 과도하게 보상하지 않음.
- 보스/특수 사건: 출처가 중요한 연구 표본·설계 정보·특수 회수 대상.
- 생산 시설/교환: 고갈된 폐허를 매번 뒤지지 않아도 되는 안정적인 소모품 기반.

탐사도는 새 세부장소 최초 조사에도 한 번 기여하도록 확장하되, 같은 지점을 반복해서 오르는 우회는 금지한다. 현재 5% 단위와 새 기여량을 합쳤을 때 임계값 도달 속도를 다시 측정한다. 이미 조사한 세부장소의 구 탐사도 소급은 일괄 보상하지 않고 저장 마이그레이션 정책으로 처리한다.

확정 보상의 고정 수량은 핵심 레시피의 최소 투입량을 기준으로 산정한다. 다만 보상 하나가 모든 입력·설비·연료를 전부 해결해서는 안 된다. 고위험 지역은 단순 수량 배수뿐 아니라 전문 공급처/지름길/선택권으로 차별화한다.

## 6. 첨부 대화씬을 반영한 UI 명세

### 현행과 차이

`NPCDialogueModal._render()`는 이미 배경·큰 인물·우측 대화/의뢰/거래 패널이 있다. `css/npc-dialogue.css`는 전체 화면 안의 두 칼럼 박스다. 첨부는 장소 배경이 화면 전체를 차지하고 우측의 작은 독립 패널이 떠 있는 구도다. 기존 구조를 활용해 공통 장면 렌더러를 분리한다.

`QuestSystem`은 questStarted/questCompleted를 발행하고, 분기는 `ModalManager.showBranchChoice()`가 별도 일반 모달로 처리한다. `CinematicScene.show()`는 활성 중 새 장면을 건너뛰며 콜백을 즉시 호출한다. 중요한 퀘스트/분기를 여기에 그대로 몰아넣지 않는다.

### 레이아웃

- 기준: 1920×1080 Scale 유지. 장소 배경은 전체 장면, 인물은 왼쪽~중앙의 약 60% 영역. 얼굴이 잘리지 않도록 인물별 object-position 지정 가능.
- 우측 패널: 폭 약 480px, 우측 여백 80px, 화면 중하단 배치. 내용 증가 시 최대 높이 820px 안에서 본문만 스크롤. 버튼/나가기 영역은 유지.
- 상단 원형 초상·이름, 짧은 상황 대사, `[의뢰]`, `[진행]`, `[보고]`, `[정보]`, `[거래]`, `[떠나기]` 중 상황에 맞는 3~5개 선택지.
- 의뢰 상세 선택 시 같은 패널에서 목표·재료·설비·효과를 보여주고 뒤로 가기 제공. 별도 모달을 겹치지 않는다.
- 게임 내 앰버/청색 의미와 기존 `--panel-glass`, `--panel-metal`, `--accent-primary`, `--text-info` 사용. 첨부의 청록 강조는 선택 상태의 차가운 강조로 해석하되 새 전역 팔레트는 만들지 않는다. 장식 균열·글리치가 글자를 가리지 않게 한다.
- 이미지의 검은 배경·인물을 통째로 배경으로 쓰지 않는다. 실제 장소·NPC 자산을 분리 사용한다. 기존 초상 없으면 작은 초상/실루엣으로 폴백. 이미지 속 박민수를 실제 NPC로 추가하지 않는다.

### 진행 흐름

1. 주요 퀘스트 시작: 배경+화자+요청. 현재 자동 시작 모델과 충돌하지 않도록 첫 적용은 '요청 확인/목표 보기'로 구성한다. 수락제 도입은 별도 상태 전이가 필요하다.
2. 진행 중: 부족한 공정과 수급 단서 제시. 재료를 얻을 때마다 장면을 자동 팝업하지 않는다.
3. 단계 보고: 세계의 변화와 협력자의 반응. 실제 제작/치료/설치 상태를 읽는다.
4. 분기: 얻는 것·포기하는 것 표시. 선택 시 한 번만 적용. 닫기나 UI 재렌더로 선택을 확정하지 않는다.
5. 완료: 보상은 시스템에서 한 번 지급하고, 장면 재열람은 표시만 수행한다.

새 공통 `DialogueScene`은 표시·입력만 담당하고 퀘스트 완료, 치료, 거래, 영입은 기존 시스템/새 도메인 서비스가 담당한다. 장면 대기열은 전투/다른 필수 모달 이후 열며 저장·불러오기에서도 미결 분기를 복원한다. 한 큐의 소유자가 입력과 모달 상태를 관리한다.

### UI 검수

- NPC 대화, 의사 시작/진행/보고, 군인 분기, 거래, 치료가 같은 구조로 표시된다.
- 긴 한국어 대사·선택지, 선택지 5개, 이미지 없음, 장소 이미지 없음에서 겹침이 없다.
- Tab 순환, Esc 정책, 선택 후 원래 포커스 복원, 마우스/터치 버튼 동작 일치.
- 강제 분기는 선택 없이 사라지지 않으며 저장 후 재개 가능. 장면 대기 중 완료 이벤트가 두 번 와도 보상 중복 없음.
- 1920×1080 및 실제 앱 축소 화면에서 버튼과 글자가 읽힌다. 주요 텍스트 14px 이상 토큰을 유지하고 상세판에 모든 정보를 몰아넣지 않는다.

## 7. 완료 조건과 리스크

- 6직업 모두 첫 대표 행동, 중간 프로젝트, 선택한 후반 분기가 제작→사용→효과로 연결돼야 한다.
- 중간재는 원칙적으로 두 소비처 이상이거나 출처/서사상 분명한 전용 의미를 가진다.
- 구와 세부장소 드랍 변경은 원료 최소 공급 보장 후 적용한다. 기판·소금·필터·흙·종자의 확정/반복 경로를 확인한다.
- 필수 목표가 한 번뿐인 보상 소진 때문에 영구 차단되지 않는다. 직접 제작/거래/대체 회수 중 하나를 둔다.
- 랜드마크 반복 수급과 일반 제작·분해로 물자가 무한 증가하는 순환이 없는지 수량·시간·도구 내구까지 검사한다.
- 새 유지비는 상위 설비와 협력자에 의해 관리 빈도가 줄어야 한다. 모든 직업이 같은 일일 정비를 하게 만들지 않는다.
- 세이브 변경 시 탐사도·청구 이력·진행 퀘스트·환자 상태 보존. 보상표 수정만으로 이미 받은 고급 부품을 회수하지 않는다.
- 특정 지역 반복이 최적이 되는지, 원료 부족으로 오히려 제작이 줄어드는지 실제 플레이 결과로 판단한다.

## 8. 이번 확인 범위와 한계

모든 아이템의 모든 사용 경로, 거래·보스·비밀 조합의 전체 경제, 모든 시즌의 최단 동선은 이번 정적 조사만으로 증명하지 않았다. 전수 데이터 추출을 전수 플레이 검증으로 표현하지 않는다. 지역별 수량은 제안이며 실제 난이도는 후속 시뮬레이션과 플레이테스트로 확정한다.
