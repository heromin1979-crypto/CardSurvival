# 랜드마크 드랍 아이템 및 확률 — 자체 표 + 세부장소 표

> **출처:** `js/data/landmarks.js` (LANDMARK_DATA — `lootTable`/`lootCount`, `subLocations[].lootTable`/`lootCount`)
> **추첨 로직:** `js/systems/ExploreSystem.js` (`rollWeightedLoot`, `_generateLandmarkLoot`, `_generateSubLocationLoot`, `_grantFirstEnterReward`)
> **생성 스크립트:** `scripts/generate_landmark_loot_doc.mjs` (데이터 변경 후 재실행하면 이 문서가 갱신된다)

## 1. 드랍 표는 3계층으로 완전히 분리돼 있다

탐색 버튼은 하나(`exploreCurrentDistrict`)지만, **어디에 서 있느냐**에 따라 서로 다른 표를 굴린다.
세 표는 데이터·코드 모두 분리돼 있어 한쪽을 고쳐도 나머지는 영향을 받지 않는다.

| 계층 | 데이터 위치 | 추첨 함수 | 언제 쓰이나 |
|---|---|---|---|
| **구(표면)** | `districts.js` → `DISTRICTS[구].lootTable` | `generateDistrictLoot` | 구에 서서 탐색 |
| **랜드마크 자체** | `landmarks.js` → `LANDMARK_DATA[키].lootTable` | `_generateLandmarkLoot` | 랜드마크 안(세부장소 밖)에서 탐색 |
| **세부장소** | `landmarks.js` → `...subLocations[].lootTable` | `_generateSubLocationLoot` | 세부장소에 처음 진입 |

### 공통 추첨 절차 (`rollWeightedLoot`)

랜드마크 자체 표와 세부장소 표는 **같은 함수**를 쓴다.

1. `lootCount` `[min,max]` 범위에서 픽 수를 균등 추첨한다 (세부장소는 여기에 `stockRatio`를 곱한다).
2. 각 픽마다 `weight / totalWeight` 비율로 항목 1개를 뽑는다.
3. 수량은 `rollQty` — `minQty`가 있으면 `[minQty,maxQty]` 균등, 없으면 `qty ?? 1` 고정.
4. `contamChance`가 있으면 그 확률로 오염도 60이 붙는다 (코드는 지원, 현재 데이터에는 미사용).
5. 뽑힌 항목의 아이템 정의가 없으면 그 픽은 버려진다 (아래 표의 ⚠️ 항목).

### 세 계층의 결정적 차이

| 항목 | 구 표면 (`generateDistrictLoot`) | 랜드마크 자체 (`_generateLandmarkLoot`) | 세부장소 (`_generateSubLocationLoot`) |
|---|---|---|---|
| 재획득 | 탐색할 때마다 반복 | **탐색할 때마다 반복** (제한·재고 없음) | **첫 방문 1회만** (`subLocationsLooted`, 리스폰 없음) |
| 픽 수 | 전역 `explore.lootCountMin~Max` (1~3) | 랜드마크별 `lootCount` | 세부장소별 `lootCount` |
| 재고 | 없음 | 없음 | **W3-2 재고** — `lootCount[1]`을 baseStock으로 두고 루팅 수만큼 차감, `stockRatio`로 픽 수 보정 |
| 수량 | `[minQty,maxQty]` | `[minQty,maxQty]` | `[minQty,maxQty]` |
| 자원 레벨(EcologySystem) | 표면 항목(`cls:surface`)에 배율 적용 | **미적용** | 미적용 |
| 제철 필터(`seasons`) | 적용 | **미적용** | 미적용 |
| 오염 | `contamChance` → 오염 50~100 | `contamChance` → 오염 60 | `contamChance` → 오염 60 |
| 도구·특성·스킬 보너스 픽 | 적용 (`exploreBonus`, `scavenger`, `scavenging`, 마스터리, 계절 보너스) | **전부 미적용** | 미적용 |
| 구 탐사도 | 1회분 누적 + 임계값 특수자원(`explorationYields`) | **누적 안 함** | 누적 안 함 |
| 1회 보상 | 없음 | 없음 | `firstEnterReward` (캐릭터당 1회 자동 지급) |

> ⚠️ 랜드마크 안에서 누른 탐색은 **구 자원·구 탐사도를 건드리지 않는다** — 같은 자리에서 구를 반복 채집해 구별 자원 모델을 무의미하게 만드는 것을 막기 위한 설계다 (`ExploreSystem._arriveAtDistrict` 조기 반환).
> 대신 소음·방사선·조우·보스 판정과 TP/스태미나 소모는 **서 있는 구의 수치를 그대로** 쓴다. 즉 랜드마크 자체 표는 "1 TP당 무제한 반복 채집"이 가능하니 가중치·수량을 올릴 때 주의한다.
> 자체 표가 비어 있으면 「이미 다 뒤졌다」 알림만 뜬다.

> **기대 등장(min~max픽)** = `(Σ_{k=min..max} 1-(1-p)^k) / (max-min+1)`. 세부장소는 재고가 가득 찬 첫 방문 기준이며, 재고 소진 시 실제 픽 수는 줄어든다.

### 데이터 에디터에서 편집하는 위치

| 표 | 에디터 위치 |
|---|---|
| 구 표면 | **장소** 탭 → 구 선택 → `lootTable (탐색 드랍 가중치)` — 자원(`cls`)·제철(`seasons`)·오염% 열 포함 |
| 랜드마크 자체 | **랜드마크** 탭 → 랜드마크 선택 → `lootTable (랜드마크 전용 드랍)` + `lootCount min/max` |
| 세부장소 | **세부장소** 탭 → 세부장소 선택 → `lootTable (세부장소 드랍)` + `lootCount min/max` |

> 세 표 모두 weight 옆에 실시간 드랍 %가 표시되고, 존재하지 않는 아이템 ID는 빨간 테두리 + 검증 탭에 잡힌다.
