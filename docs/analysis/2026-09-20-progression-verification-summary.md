# 직업 진행·수급·대화 검증 정리

## 현재 반영된 내용

기존 227개 퀘스트의 선행·분기·엔딩을 보존하며 79개 프로젝트를 설치·물자 투입·가동·반복 운영으로 연결했다. 첨부 이미지처럼 인물과 배경을 왼쪽에, 선택 패널을 오른쪽에 두는 대화 장면을 사용한다. 환자는 진단·안정화·처치·회복 단계와 치료 대안을 갖고, 지역 보상은 25구의 75개 확정 보상 및 34개 공급처로 재구성했다.

이는 대사 79개를 새로 만든다는 뜻이 아니다. 프로젝트 조작, 치료 선택, 퀘스트 이야기 분기는 다른 콘텐츠다.

## 대화 현황과 확장 방향

전체 데이터에는 퀘스트 시작·완료 문안 454곳, 이야기 분기 13곳/선택지 28개, NPC 개인 의뢰 23개가 있다. 비밀 이벤트는 37개/선택지 90개지만 별도 화면이며, 기억 14개와 직업 반응 103문안은 주로 알림·로그다. 이 수치는 배타적인 직업·엔딩을 합친 정의 수이며 한 회차의 경험 횟수가 아니다.

부족한 것은 문장 수보다 **질문하고 결정하고, 실제 행동 후 상대의 달라진 반응을 듣는 과정**이다. 직업별 핵심 대화 1개와 생활 대화 1개, 총 12개를 우선 제작·검증하고, 핵심 36개와 생활 24개로 확대하는 계획을 작성했다. 신규 60개 주제는 아직 구현되지 않았다.

| 직업 | 대화에서 결정할 일 | 실제 행동으로 확인할 결과 |
|---|---|---|
| 의사 이지수 | 긴급 안정화와 추가 진단, 당일 소모품과 장기 멸균 준비 | 실제 치료 단계·소모품·회복과 다음 환자 수용 |
| 군인 | 구조 우선순위와 보급·통신 담당 분담 | 무전 수리·전원·구조 거점·보급 재방문 |
| 소방관 | 접근로·거처 보강·급수 순서 | 방수·출입구·급수 설치 및 주민 인계 |
| 셰프 | 바로 먹일 음식과 비축, 재배와 겨울 교환 | 조리·배식·저장·운영 재료 소비 |
| 기계공 | 임시 수리와 정밀 정비, 전력 배분 | 직접 부품 제작·설치·연료·전력 소모 |
| 최형식 | 회수품 비축과 교환, 일회 거래와 공급 약속 | 분해·창고·실제 거래·후속 공급 |

대사는 첫 만남, 정보 질문, 준비 부족, 선택 직후, 행동 완료 후 재회로 나눈다. 이전 결정을 저장해 반응에 반영하고, 반복 정보 질문으로 보상이나 신뢰를 무한 획득하지 않게 한다. 직업 전용 방법 외에도 공통 대안을 둔다. 상세 규격과 의사 예시는 [대화 확장 계획](2026-09-20-dialogue-interaction-plan.md)에 있다.

## 의료와 다른 직업의 깊이 평가

의료는 기존 단일 붕대 소비에서 단계별 물품·설비·처치 대안으로 확장됐다. 그러나 처음 만나는 부상 군인은 시작 붕대로 즉시 치료하는 입문 목표다. 이를 깊은 의료 제작 경험이라고 평가하지 않는다. 이후 회복식/수액, 회수 약품/합성약/정제약, 치료소·연구·임상 경험으로 이어지는 구간에서 깊이를 판단해야 한다. 이 연결은 기능적으로 검사했지만 재미와 반복 피로도는 실제 장기 플레이 평가가 남는다.

셰프의 첫 배식도 시작 음식으로 완료할 수 있다. 첫 안내는 쉽게 유지하되 후속 대화는 재료 손질·보존·식사 요구를 경험하게 해야 한다. 군인·소방관은 초반부터 시작 구역 밖을 이동하며, 기계공은 원료·도구·숙련·제작 실패 때문에 비용 편차가 크다. 모든 직업에 똑같은 제작 단계 수를 강요하기보다 서로 다른 판단과 소비 흐름을 주는 것이 적절하다.

## 실제 검증 결과와 한계

- 초반 경제 24조건(6직업×봄/겨울×일반/초기 탐색 불발): 실제 시작 물품으로 첫 목표 실행 성공. 목표 퀘스트 접근만 열고 전투를 제외한 구간 시험이며 재료를 추가 지급하지 않았다.
- 중반 24조건: 원료·도구·숙련을 갖춘 준비 상태에서 제작·공급·설치·가동·저장 복원을 검사했다. 초반부터 이어진 연속 세이브가 아니다.
- 최종 기계공은 초반 29~51TP, 군인 13~19TP, 소방관 15~24TP였다. 통나무·잔해 분해와 인접 강북 수급을 이용한 최종24표본은 모두 지역 탐색도 최대30% 이내에 첫 목표를 끝냈다. 원료나 드랍량을 추가하지 않고 동선을 바꾼 결과다.
- 초기 기계공 겨울 불리 정책은 81TP·은평100%·오염수 음용까지 필요했다. 대체 경로를 적용하자51TP·은평30%/강북15%·음용0/감염0으로 줄었다. 이 차이는 드랍량뿐 아니라 **분해·지역 이동·부족 재료 안내**가 체감 난이도를 좌우한다는 근거다. 이전표본도 economic-pre-salvage-policy.json에 보존했다. 여러 난수나 전투까지 일반화한 보장은 아니다.
- 추가 셰프 4조건에서는 시작 완성 음식을 모두 실제 소비한 뒤 약초·야생 베리를 탐색하고 시작 소금을 써 샐러드를 제작·배식했다(19~75TP). 시작 음식을 제공하는 2TP 안내 목표와 구분한다.
- 작업대를 실제 분해한 뒤 회수 원료와 다른 지역 물자를 모아 재제작하는 기계공 2표본도 실행했다(전체 경로93/96TP). 무보상 삭제로 모든 도구를 잃는 경우나 모든 핵심 품목 분실을 검증한 것은 아니다.
- 전투·선행 퀘스트·장기 생존을 포함한 24조건 캠페인 완주는 검증하지 않았다. 모든 중반 원료의 자연 획득 동선과 장기 반복 운영의 순수익도 확정하지 않았다.

위 TP는 사용한 탐색·휴식 정책과 난수 표본의 실행값이며 최단 경로나 평균 플레이 시간은 아니다. 단계별 원시 행동과 TP는 [경제 시험 보고서](progression-execution/task-6-report.md)에 남겼다. 이 결과만으로 모든 확정 보상 수량이 최적이라고 주장하지 않는다.

## 검수에서 발견해 수정한 문제

1. 고급 레시피 자동 해금 목록 누락: 기본·고급·히든을 합친 `GameData.blueprints`를 검사하도록 통일했다.
2. 겨울 셰프 진행 잠금: 재배 중단기에 고철 3개+소금 1개를 채소 2개+약초 1개로 교환하는 운영을 연결했다. 3TP와 재고 보충 주기 72TP가 있으며 물을 소비해 재배한 것으로 처리하지 않는다. 이 실제 운영으로 후속 급식 목표에 진입한다.
3. 치료 레벨업 중간 자동저장: 완치 전이·기여 선택·TP 소비가 끝난 상태를 함께 저장하도록 치료 행동의 저장 경계를 묶었다.

독립 재검수는 94개 집중 테스트와 별도 Node assertion 36개로 통과했다. [재검수 보고서](progression-execution/task-6-rereview.md).

## 최종 기능 검사

- 전체 테스트 최초 실행에서 278파일 중 6파일/15테스트 실패를 확인했다. 변경 계약을 검사하던 5파일을 실제 치료·보상·프로젝트 경로에 맞춰 보완했다.
- 수정 후 이미지 자산 검사 4파일을 제외한 재실행: 275파일 중 274통과, 3,816테스트 통과/기존 UI 테스트 1실패/3건 건너뜀. 제외한 이미지 4파일은 앞선 실행에서 62테스트 통과했으며 해당 자산은 변경하지 않았다. 전체 테스트가 모두 통과한 상태는 아니다.
- 남은 기존 실패는 `CompanionSidePanel.test.js`의 CSS inset 정규식 계약이다. 이번 변경 이전에도 재현됐다.
- 데이터 검증 오류 0/기존 경고 183. 효과 연결 96개와 에디터 아이템 설명 208필드 검사 통과.
- 최종 웹 빌드 성공(20.90초). 실제 Chromium 대화 E2E와 겨울 교환 E2E 성공, 페이지 오류 0. 844/1280/1920 화면 및 저장·분기·치료·기여 선택을 검사했다.

변경은 로컬 미커밋 상태다. 신규 대화 콘텐츠 제작과 장기 밸런스 검증은 위 기능 검증과 분리해 관리한다.
