# SPEC — 무엇을 만드는가

> 이번 라운드의 기획서. 한 번 정하면 거의 고치지 않는다.
> 저장소 루트의 `DESIGN.md`(디자인 시스템)와 다른 파일이다. 헷갈리지 않는다.

## 1. 한 줄 정의

메인 플레이 화면(`#screen-main`)의 레이아웃과 정보 구조를
`docs/loop/reference/main-screen-target.jpg` 에 가깝게 맞춘다.

## 2. 만드는 것

- **목표 이미지: `docs/loop/reference/ui-refs/main-screen-v2.png`**
- 구버전 목표: `docs/loop/reference/main-screen-target.jpg` — 비교용. **둘이 다르면 v2 가 이긴다.**
- 현재 상태 (2026-09-06 캡처): `docs/loop/reference/main-screen-current-2026-09-06.png`
- 작업 대상은 `docs/loop/INBOX.md` 에 항목으로 적힌 것뿐이다.

`docs/loop/reference/ui-refs/` 에 목표 이미지가 7장 있지만 **이번 라운드가 보는 것은
`main-screen-v2.png` 하나뿐이다.** 나머지 6장(전투·장비×2·퀘스트×2·대화)은 다음 라운드
후보이며, 그중 셋은 UI 가 아니라 시스템 작업이다. 이유는 `ui-refs/README.md` 에 적었다.
**다른 화면이 눈에 들어와도 이번 라운드에 손대지 마라.**

건드려도 되는 곳:
- `css/` 전체
- `js/screens/Basecamp.js`, `js/screens/Main.js` (보드·사이드바 골격)
- `js/ui/` 의 렌더러·컴포넌트 (`BoardRenderer.js`, `CardFactory.js`, `HeaderBar.js`, `QuestPanel.js`, `js/ui/components/`)
- `js/systems/` — 화면 표시에 관여하는 부분 (예: `OnboardingSystem.js` 의 안내 툴팁)

`js/systems/` 는 게임 로직도 함께 들어 있는 디렉터리다. 열어 둔 이유는
화면 문제의 원인이 거기 있을 때 CSS 로만 우회하면 반쪽짜리 수정이 되기 때문이다.
대신 두 가지를 지킨다.

- INBOX 항목이 요구하는 것만 고친다. 지나가다 보이는 로직을 손보지 않는다.
- `npm test` 3378건이 회귀를 잡는다. 하나라도 깨지면 커밋하지 않는다 (⑥).

## 3. 만들지 않는 것

- **게임 데이터**: `js/data/` 는 건드리지 않는다. 아이템·레시피·퀘스트·구 데이터가
  같이 움직이면 화면 문제인지 데이터 문제인지 가릴 수 없다. 밸런스 수치
  (`js/data/gameBalance.js`)도 여기 포함이다.
- **색·폰트·간격 토큰 신설**: `css/variables.css` 에 없는 값을 새로 만들지 않는다.
  목업의 팔레트는 이미 `DESIGN.md` 와 일치한다. 새 토큰이 필요하면 INBOX 에 남긴다.
- **한/영 병기 (`nameEn`)**: 이번 라운드 범위 밖이다. 아래 4절 참조.
- **전투·탐색·모달 화면**: 메인 플레이 화면만 한다.

- **Confluence 패치 노트**: 이 라운드의 커밋은 패치 노트 페이지를 만들지 않는다.
  `CLAUDE.md` 7절이 게임 동작이 바뀌는 커밋마다 요구하지만, **이 라운드에 한해
  그 조항보다 이 문장이 우선한다.** 커밋 메시지 끝에 한 줄만 남긴다:
  `UI 라운드 — 패치 노트는 라운드 종료 후 한 장으로 묶는다 (SPEC 3절).`

  이유는 둘이다. INBOX 13건은 모두 같은 화면의 레이아웃 조정이라 항목마다
  페이지를 만들면 마스터 패치 노트가 UI 조정으로 뒤덮인다. 그리고 무인 세션에는
  Atlassian MCP 권한이 없어 호출 자체가 거부된다 — 매 바퀴 같은 벽에 부딪힌다.

  라운드가 끝나면(INBOX 0건) **사람이** 13건을 묶어 한 장으로 만든다. 루프는 만들지 않는다.

## 4. 범위에서 뺀 것과 이유

**한/영 병기.** 목업은 모든 카드와 섹션에 영문명을 병기한다. 그런데
`nameEn` 필드는 저장소 어디에도 없다 (아이템 589개 전부 0건, i18n 디렉터리 없음).
구현하려면 아이템 589개 + 랜드마크 45개에 영문명을 새로 채워야 하고, 그건
`js/data/` 작업이라 3절에 걸린다. 별도 라운드로 뺀다.

**배경 사진 레이어.** 목업은 폐허 사진이 전면에 깔려 있다. 에셋이 없다.
`assets/images/` 에 배경이 추가되면 그때 INBOX 로 들어온다.

## 5. 완성의 모습

INBOX 의 항목이 0건이 되고, 캡처한 화면이 목표 이미지와
레이아웃(3컬럼) · 섹션 구성 · 카드 정보 밀도에서 같은 골격을 갖는다.

## 6. 기술 제약

- 바닐라 JS 모듈, CSS 변수, Vite. 고정 해상도 1920×1080 (Scale 방식)
- 새 의존성을 넣지 않는다
- 검사: `npm test`, `node js/data/validate.js` 통과해야 커밋
- 화면 확인: 아래 방법으로 캡처해 이미지를 직접 읽는다

## 7. 화면 캡처 방법

`tools/capture-main-screen.mjs` 가 이미 있다. vite 를 띄우고 새 게임 → 슬롯 1 →
`#ss-btn-primary` → `#btn-start` → 오프닝 선택지 순으로 눌러
`screen-main` 까지 들어간 뒤 스크린샷을 남긴다. 셀렉터가 바뀌면 이 파일을 고친다 (`SHOT_DIR` 환경변수로 저장 위치 지정).
